# Gemini 3 모델 전환

웹앱의 모든 인공지능 기능은 `src/lib/ai.ts`를 통해 호출한다. 기본 모델은 `gemini-3.1-flash-lite`, 대체 모델은 `gemini-3-flash-preview`다. 질문 분류, 번역, 수업 자료 생성, 개인·학급 리포트, 포인트 분석, 질문놀이 모두 새 경량 모델로 시작한다. 설정 화면에서 새 Gemini 3 Flash를 직접 선택한 경우에는 그 설정을 존중한다.

## 기존 설정 호환

교사, 담당 학급, 시연 계정, 전역 설정에 저장된 이전 모델 값은 읽을 때 새 기본 모델로 변환한다. 데이터베이스를 일괄 수정하거나 교사가 키를 다시 등록할 필요는 없다. 이미 열린 이전 설정 화면에서 보낸 Gemini 2.5 모델 값도 설정 저장, 연결 테스트, 질문 분류 요청에서 새 기본값으로 변환한다. 과거 분석 기록의 실제 사용 모델 표시는 그대로 유지한다.

## 자동 복구

- 모델 혼잡, 분당 제한, 서버·네트워크의 일시 오류는 같은 모델에서 한 번 재시도하고 실패하면 대체 모델로 전환한다.
- 모델 종료·미지원, 모델별 기능 미지원, 일일 할당량 초과는 같은 모델을 반복 호출하지 않고 대체 모델로 전환한다.
- Gemini의 일반적인 400 `INVALID_ARGUMENT` 요청 거절도 대체 모델에서 한 번 시도한다. 두 모델 모두 거절하면 중단하며, 잘못된 API 키와 권한 오류는 전환 대상에서 제외한다.
- 빈 응답, 잘못된 JSON, 객체·배열 형식 불일치, 기능별 필수 항목 누락도 대체 모델에서 다시 생성한다.
- 출력이 잘리면 기존 토큰 상한 확대 정책을 한 번 적용한다. 여전히 실패하면 대체 모델을 시도한다. 시연 계정의 2,048토큰 상한과 실행당 사용량 계산은 유지한다.
- 두 모델이 모두 실패하면 기존 오류 처리 흐름으로 반환한다. 불완전한 분석을 정상 결과로 저장하지 않는다. 인증 실패와 안전 차단은 즉시 알린다.
- 대체 모델 전환은 요청당 한 번으로 제한한다. 분할 분석은 기존 전체 실행 시간·호출 횟수 제한을 공유한다.

JSON 문법 검사는 공통 호출 계층에서 수행한다. 질문 분류, 번역, 연습 출제, 개인·학급 리포트, 포인트 분석, 수업 안내 생성, 미스터리 박스와 이야기 대답 판정은 기존 기능별 검사를 `validateResponse`로 연결한다. 미스터리 박스는 독립 검증 단계와 서버 사실표를 유지한다. 수업 안내는 번호·개수 검사와 제한된 보완 요청을 유지한다.

## 탐구설계의 대량 질문 묶기

질문 수에 따라 커지는 배열의 `maxItems`, 정렬의 `minItems`, 원본 번호 전체의 `enum`은 응답 형식에 넣지 않는다. Gemini는 큰 배열 제약이 중첩된 응답 형식을 400 오류로 거절할 수 있다. 모든 원본 번호의 정확한 포함, 누락·중복·새 번호 금지, 결과 개수와 대표 질문 길이 제한은 서버의 `normalizeSequencedQuestions` 검사에서 유지한다.

입력의 긴 데이터베이스 번호는 실행 중에만 `q1`, `q2` 같은 짧은 임시 번호로 변환한다. 결과 검증 때 서버가 원래 번호로 복원하므로 저장된 질문과 교사가 편집한 묶음의 연결은 유지한다. 모델이 알 수 없는 임시 번호를 반환하면 채택하지 않는다.

묶기와 정렬의 완전성 검사도 공통 호출 계층의 `validateResponse`에서 실행한다. Flash-Lite가 불완전한 결과를 반환하면 Flash로 전환한다. 두 모델 모두 불완전할 때만 누락·중복 번호 피드백을 포함해 한 번 보완한다. 안전 차단은 보완하지 않는다. 각 생성의 통신 제한은 90초, 전체 생성 세션은 240초이며 라우트는 최대 300초를 허용한다. 끝까지 검증하지 못하면 원본 질문 전체를 개별 항목으로 보존하고 화면에 실패 안내를 표시한다.

모델 전환과 보완 뒤에도 일부 원본만 빠졌다면, 유효한 묶음에 빠진 원본을 개별 질문으로 추가한 뒤 전체 완전성을 다시 검사한다. 실제로 합쳐진 묶음이 있고 번호·중복·내용 검사까지 통과한 결과만 사용한다. 잘못된 번호나 중복된 원본은 이 복원 절차로 통과할 수 없다. 의미가 확인되지 않은 질문을 임의로 다른 묶음에 끼워 넣지 않는다.

## 상세 리포트의 질문수업별 분석

학급 분석과 학생별 분석은 요약뿐 아니라 요청한 모든 분석 항목의 존재와 비어 있지 않은 문자열을 검사한다. 학급 주제 배열도 검사한다. 누락·빈 항목·잘못된 자료형은 Flash 전환을 유발하며, 두 모델 모두 검증에 실패하면 기존 저장된 분석을 덮어쓰지 않는다. 저장되는 `analysisModel`은 실제 성공한 모델이다. 교사가 Flash를 직접 선택한 설정도 그대로 적용한다.

설명 자료가 없는 항목은 자료가 없다는 사실과 분석 한계를 서술하도록 요청한다. 각 호출은 60초와 4,096토큰을 허용하며 시연 계정의 2,048토큰 상한은 유지한다. 단건과 일괄 분석 라우트는 최대 300초를 허용한다. 일괄 학생 분석은 모델 전환 시간까지 확보하도록 요청당 한 학생씩 처리하고, 화면이 다음 위치부터 이어서 전체를 분석한다.

## 요청 옵션

이전 `thinkingBudget: 0`은 `ThinkingLevel.MINIMAL`, 그 외 기존 사고 예산은 `ThinkingLevel.LOW`로 변환한다. 품질 작업의 기본 사고 수준은 낮은 수준이다. 호출부에서 `thinkingLevel`을 명시하면 해당 값을 우선한다. 사고 예산과 사고 수준을 동시에 보내지 않는다. 이전의 1 미만 온도는 Gemini 3 권장값인 1로 보정한다.

공식 모델 식별자와 지원 기능은 [Gemini 3.1 Flash-Lite 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite), 사고 설정·온도 권장값은 [Gemini 3 전환 안내](https://ai.google.dev/gemini-api/docs/gemini-3)를 참고한다.

## 검증 범위

자동 테스트는 기존 설정 변환, 혼잡·할당량 처리, 모델 사용 불가, 응답 형식 실패, 출력 잘림, 실제 사용 모델 기록, 인증·안전 오류 처리, 시연 계정의 사용량·출력 상한을 확인한다. 타입 검사, 린트, 전체 단위 테스트와 커버리지 기준, 프로덕션 빌드를 실행한다.

실제 저장된 키로 두 모델의 질문 분류, 128토큰 게임 판정, 2,048토큰 리포트 요청을 검증했다. 공통 호출 계층으로 개인 리포트를 생성하고, 경량 모델의 사용 불가 오류를 주입한 뒤 실제 Gemini 3 Flash 응답으로 복구되는 것도 확인했다. 이 검증에는 예시 활동만 사용했으며 결과를 데이터베이스에 저장하지 않았다.

대량 질문 개선에서는 실제 수업의 학생 질문 114개로 묶기와 학급 리포트를 검증했다. Flash-Lite 실패를 주입한 뒤 실제 Flash 응답으로 복구되는 묶기·학급 리포트와 예시 학생 리포트도 검증했다. 묶기 결과는 원본 114개를 모두 보존했다. 이 검증 결과도 데이터베이스에 저장하지 않았다.
