# 윈도우 USB 시연 실행판 설계

## 목표

윈도우 컴퓨터에서 USB의 `program/index.html`을 실행하면 로그인 정보를 입력하지 않고
배포된 질문연구소의 김질문 학생 화면으로 이동한다. 시연 계정과 활동 자료는 일반 계정과
논리적으로 분리하며, 비밀번호와 인공지능 키는 USB와 브라우저에 저장하거나 노출하지 않는다.

## 실행 조건

- 윈도우 10과 윈도우 11의 최신 엣지 또는 크롬을 지원한다.
- 안드로이드 태블릿의 최신 크롬에서도 같은 웹앱을 사용할 수 있다.
- 별도 설치 프로그램이 아닌 표준 웹브라우저 실행을 지원 범위로 삼는다.
- 인터넷 연결이 반드시 필요하다.
- 시작 파일은 `QuestionLab/program/index.html`이다.
- 시작 파일은 `https://questioning-based-inquiry.vercel.app/demo/launch`에 연결한다.
- 자동 이동이 차단되면 같은 주소를 여는 `질문연구소 열기` 버튼을 표시한다.
- USB에는 노드 실행 환경, 데이터베이스, 사용자 비밀번호, 인공지능 키를 넣지 않는다.

## 접근 방식

검토한 방식은 다음 세 가지다.

1. 현재 운영 배포 안에 시연 전용 계정 범위를 만드는 방식
2. 별도 배포와 별도 데이터베이스를 만드는 방식
3. 전체 웹앱과 데이터베이스를 윈도우 실행 프로그램으로 묶는 방식

이번 구현은 첫 번째 방식을 사용한다. 현재 웹앱의 학교와 학급 범위 조회를 유지하면서
사용자에게 시연 여부를 추가하고, 전체 순위처럼 학교 범위를 벗어나는 조회에는 시연 여부를
반드시 적용한다. 별도 데이터베이스는 가장 강한 분리를 제공하지만 현재 배포 자료 구조와
보안 검사문이 기본 데이터베이스 영역을 전제로 하므로, 별도 배포를 동시에 운영하면 관리와
배포 실패 위험이 커진다. 윈도우 실행 프로그램 방식은 인공지능 키 보호와 서버 기능 유지가
어려워 이번 제출 목적에 맞지 않는다.

- 교사가 배포한 핵심 생각, 핵심 문장, 핵심 질문, 탐구 질문과 학생용 이해 자료를 만든다.

- 혼자 하기, 인공지능과 함께하기, 친구와 함께하기 질문놀이 완료 기록을 최근 14일에
  나누어 만든다.
- 인정 질문과 활동 수, 받은 포인트, 전체 포인트가 서로 일치하도록 만든다.
- 김질문 학생의 대시보드, 질문탐구, 질문놀이 학습 기록이 빈 화면으로 보이지 않게 한다.

## 자료 분리

`User` 자료에 `isDemo` 값을 추가한다. 기존 사용자는 기본값 `false`를 가지므로 기존 자료의
내용과 식별값은 바뀌지 않는다. 시연 교사와 학생만 `true`를 가진다.

- 시연 사용자 조회는 `isDemo: true`만 포함한다.
- 일반 사용자 조회는 전체 학교 순위에서도 `isDemo: false`만 포함한다.
- 시연 사용자의 전체 순위는 시연 사용자 안에서만 계산한다.
- 질문, 답변, 수업, 질문놀이 기록은 시연 사용자 식별값에만 연결한다.
- 시연 학교 이름은 회원가입에서 사용할 수 없는 예약 이름으로 처리한다.
- 시연 계정에서는 비밀번호 변경, 회원 탈퇴, 교사 설정 변경을 허용하지 않는다.
- 기존 일반 계정의 로그인 방식과 세션 값은 그대로 유지한다.

## 자동 로그인

인증에는 기존 인증 도구의 시연 전용 자격 제공자를 추가한다.

1. `index.html`은 주소 조각에 시연 실행 표를 넣어 `/demo/launch`를 연다.
2. 주소 조각은 웹 서버 요청과 다른 주소로 이동할 때 자동 전송되지 않는다.
3. 시연 실행 화면은 주소 조각을 읽고 같은 출처의 인증 주소로 전송한다.
4. 서버는 받은 값을 해시한 결과를 서버 환경 변수의 해시와 일정한 시간으로 비교한다.
5. 실행 가능 기간, 시연 기능 활성화 값, 요청 횟수 제한을 함께 확인한다.
6. 검사가 성공하면 4학년 1반 1번 김질문 계정으로 보안 쿠키 세션을 만들고
   `/student-dashboard`로 이동한다.
7. 실패하면 원인을 구분해 `사용 기간이 끝났습니다`, `실행 권한을 확인할 수 없습니다`,
   `인터넷 연결을 확인해 주세요` 중 알맞은 안내와 다시 시도 버튼을 표시한다.

실행 표는 USB를 가진 사람이 확인할 수 있으므로 완전한 비밀로 취급하지 않는다. 이 표로는
김질문 학생 계정만 열 수 있고 교사 또는 일반 학생 계정에는 사용할 수 없다. 서버에서
즉시 사용 중지하거나 새 값으로 바꿀 수 있으며, 기본 만료 시각은
`2026-12-31 23:59:59` 한국 시각으로 설정한다.

## 인공지능 키와 사용 제한

김질문 학생은 인공지능 키를 입력하지 않는다. 서버는 `DEMO_AI_SOURCE_EMAIL`로 지정된
교사 계정의 현재 인공지능 설정을 서버 안에서만 조회해 사용한다. 기본 지정값은
`climbing1126@gmail.com`이며 키 문자열은 응답, 기록, 주소, HTML에 포함하지 않는다.

시연 사용자는 다음 제한을 적용한다.

- 분당 최대 10회의 인공지능 요청
- 한국 시각 기준 하루 최대 120회의 인공지능 요청
- 요청 한 번당 최대 출력량 제한
- 교사 전용 생성과 설정 주소 접근 금지
- 하루 한도 자료는 별도 표에 원자적으로 기록
- 한도를 넘으면 외부 인공지능 요청을 보내지 않고 학생이 이해할 수 있는 안내 반환

기존 일반 사용자의 인공지능 설정 선택 순서와 사용량에는 이 제한을 적용하지 않는다.

## USB 폴더

최종 결과는 `/Users/youngmini/Documents/QuestionLab`에 만든다.

```text
QuestionLab/
├─ media/
│  ├─ image/
│  │  ├─ login-inquiry-hero.png
│  │  └─ question-learning-cover.png
│  └─ sound/
└─ program/
   ├─ index.html
   └─ source/
      ├─ src/
      ├─ public/
      ├─ prisma/
      ├─ scripts/
      ├─ e2e/
      ├─ messages/
      ├─ package.json
      └─ 개발 설정 파일
```

`index.html`은 로컬 이미지 하나를 표시하고 즉시 웹앱을 연다. 자바스크립트가 꺼진 경우에도
버튼으로 열 수 있어야 한다. 웹앱이 소리 파일을 직접 사용하지 않으므로 `sound` 폴더는
비워 둔다. `source`에는 깃에 기록된 실행 소스, 데이터 구조, 검사와 개발 설정을 복사한다.
`.env.local`, 실제 비밀값, 깃 내부 자료, 설치 의존성, 빌드 결과와 사용자가 따로 만든 파일은
복사하지 않는다.

## 검사

- 시연 실행 표 검증과 만료 계산 단위 검사
- 일반 사용자와 시연 사용자 세션 값 분리 검사
- 시연 계정의 비밀번호 변경과 설정 변경 차단 검사
- 일반 순위에서 시연 사용자가 제외되고 시연 순위에서 일반 사용자가 제외되는 검사
- 자료 생성 명령을 두 번 실행해 사용자와 활동 자료가 중복되지 않는 검사
- 28명 학생의 학교, 학년, 반, 번호, 이름 검사
- 김질문 자동 로그인 뒤 학생 대시보드 이동 검사
- 실행 표 누락, 잘못된 값, 만료, 과도한 요청 오류 화면 검사
- 인공지능 키가 브라우저 응답과 USB 파일에 포함되지 않는 검사
- 윈도우 크롬과 엣지, 안드로이드 태블릿 크롬에 해당하는 화면 크기에서
  `index.html` 이동과 대체 버튼 검사

## 배포와 되돌리기

1. 데이터베이스 변경을 먼저 적용한다.
2. 시연 사용자와 학습 자료 생성 명령을 실행한다.
3. 서버 환경 변수에 실행 표 해시, 만료 시각, 사용 여부, 인공지능 설정 출처를 등록한다.
4. 웹앱을 배포하고 자동 로그인과 자료 조회를 확인한다.
5. 확인된 실행 주소 조각을 포함한 `index.html`과 매체 파일을 USB 제출 폴더에 만든다.

문제가 생기면 `DEMO_LAUNCH_ENABLED=false`로 자동 로그인을 즉시 중지할 수 있다. 시연 자료는
`isDemo: true` 범위로만 삭제할 수 있으며 일반 자료는 삭제 대상에 포함하지 않는다.
