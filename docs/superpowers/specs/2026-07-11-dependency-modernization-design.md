# 의존성 최신화 설계

## 배경

현재 서비스는 Next.js 14와 React 18을 사용하고 있다. Next.js 14는 지원이 끝났고, 현재 설치 상태의 운영 의존성 검사에는 높은 등급을 포함한 취약점이 남아 있다. 또한 구글의 이전 생성형 인공지능 도구인 `@google/generative-ai`는 유지 보수가 끝났으므로 새 도구인 `@google/genai`로 옮겨야 한다.

이번 작업은 권한 경계 보완과 데이터베이스 구조 변경보다 먼저, 실행 기반을 지원 중인 버전으로 옮기는 데 목적이 있다. 데이터베이스 행과 구조는 변경하지 않는다.

## 목표

1. Next.js, React, 인증, 검사 도구를 현재 지원되는 조합으로 갱신한다.
2. 기존 페이지, 로그인 보호, API 응답 계약을 그대로 유지한다.
3. 구글 생성형 인공지능 연동을 유지 보수 중인 도구로 교체한다.
4. 두 변경을 서로 독립적으로 배포하고 되돌릴 수 있게 나눈다.
5. 전체 검사와 미리 보기 배포에서 동작을 확인한 뒤 운영에 반영한다.

## 범위

### 첫째 단계: Next.js 실행 기반 갱신

다음 버전을 목표로 한다.

| 항목 | 현재 | 목표 |
| --- | --- | --- |
| `next` | `14.2.35` | `16.2.10` |
| `react` | `18.3.1` | `19.2.7` |
| `react-dom` | `18.3.1` | `19.2.7` |
| `next-auth` | `5.0.0-beta.22` | `5.0.0-beta.31` |
| `next-intl` | `4.13.0` | `4.13.2` |
| `eslint` | `8.57.0` | `9.39.4` |
| `eslint-config-next` | `14.2.35` | `16.2.10` |
| `@types/react` | React 18 계열 | `19.2.17` |
| `@types/react-dom` | React 18 계열 | `19.2.3` |

`package-lock.json`으로 실제 설치 버전을 고정한다. 실행 환경은 Next.js 16이 요구하는 Node.js `20.9.0` 이상을 사용한다. 현재 로컬과 지속 통합 환경의 Node.js 24는 이 조건을 만족한다.

주요 변경은 다음과 같다.

- `package.json`과 `package-lock.json`의 의존성을 갱신한다.
- `.eslintrc.json`을 `eslint.config.mjs` 기반의 평면 설정으로 옮긴다.
- `next lint` 대신 ESLint 명령줄 실행을 사용하도록 검사 명령을 바꾼다.
- `next.config.js`의 `experimental.serverComponentsExternalPackages`를 안정 설정인 `serverExternalPackages`로 옮긴다.
- `src/middleware.ts`를 Next.js 16의 `src/proxy.ts` 규약으로 옮기고, 현재의 경로 보호와 공개 경로 판정을 그대로 유지한다.
- Next.js 16에서 비동기가 된 `params`, `searchParams`, `cookies`, `headers` 사용 지점을 찾아 공식 규약에 맞춘다.
- Turbopack을 기본 개발 및 빌드 방식으로 사용한다. 호환되지 않는 문제가 실제로 확인될 때만 임시로 `--webpack` 되돌림을 사용하고, 원인과 제거 조건을 기록한다.
- React 19의 형식 검사에서 드러나는 호환 문제만 고친다. 화면 구조나 기능을 함께 바꾸지 않는다.

인증 처리는 기존 `next-auth` 설정과 세션 계약을 유지한다. `src/lib/auth-edge.ts` 같은 보조 모듈은 `proxy.ts`의 Node.js 실행 환경에 맞추는 데 꼭 필요한 경우에만 손본다. 로그인 주소, 쿠키 이름, 세션 값, 보호 경로 목록은 바꾸지 않는다.

### 둘째 단계: 구글 생성형 인공지능 도구 교체

`@google/generative-ai` `0.24.1`을 제거하고 `@google/genai` `2.11.0`을 설치한다. 외부 호출 차이는 `src/lib/ai.ts` 안에서 흡수해 나머지 서비스가 도구별 형식을 알지 않게 한다.

다음 동작은 그대로 유지한다.

- 기존 환경 변수와 교사별 설정에서 API 키를 읽는 순서
- 현재 모델 선택과 대체 모델 재시도 순서
- 질문 생성과 평가에 사용하는 지시문과 입력 값
- 성공 응답을 내부 결과로 바꾸는 방식
- `429`와 `503` 계열을 일시 오류로 판정해 재시도하고, 그 밖의 오류는 호출부로 전달하는 방식

새 도구의 응답 구조가 다르므로, 텍스트 추출과 오류 판정은 작은 내부 변환 함수로 분리한다. 호출부에는 기존 내부 계약만 노출한다.

## 작업 경계

이번 설계에는 다음 항목을 포함하지 않는다.

- 학교와 학급 단위 권한 경계 보완
- 교사 가입 제한과 학생 점수 수정 권한 변경
- 게임 방 갱신의 원자성 보완과 데이터베이스 구조 변경
- API 키 암호화와 데이터베이스 실행 계정 분리
- 분산 요청 제한과 세션 강제 무효화
- 화면 재설계나 새 기능 추가

이 항목들은 의존성 최신화가 안정적으로 배포된 뒤 별도 설계와 변경으로 진행한다.

## 변경 단위와 배포 순서

두 단계는 별도 커밋으로 만든다.

1. Next.js 실행 기반 갱신 커밋
2. 구글 생성형 인공지능 도구 교체 커밋

첫째 단계를 모두 검증한 뒤 둘째 단계로 넘어간다. 둘째 단계에서 문제가 생기면 첫째 단계는 유지한 채 둘째 단계만 되돌릴 수 있어야 한다. 각 단계가 끝날 때 잠금 파일과 검사 결과를 함께 확인한다.

운영 반영 전 미리 보기 배포에서 공개 화면과 인증 경계를 확인한다. 미리 보기 검증이 끝나기 전에는 운영 데이터베이스에 쓰기 요청을 보내지 않는다.

## 오류 처리와 되돌리기

- 설치 충돌은 강제 설치 옵션으로 숨기지 않는다. 서로 맞는 의존성 버전을 선택해 정상 설치가 되게 한다.
- 형식 오류와 빌드 오류는 해당 호출부를 새 규약에 맞춰 고치며, 검사 비활성화로 우회하지 않는다.
- 인증 경로 동작이 달라지면 배포를 멈추고 첫째 단계 커밋을 되돌린다.
- 인공지능 응답이나 대체 처리에 회귀가 생기면 둘째 단계 커밋만 되돌린다.
- 운영 데이터베이스 구조와 행을 변경하지 않으므로 데이터 되돌리기 작업은 발생하지 않는다.

## 검증 기준

각 단계에서 다음 명령이 모두 성공해야 한다.

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
npm audit --omit=dev
```

검사 항목은 다음과 같다.

- 전체 단위 검사와 기존 인공지능 대체 처리 검사가 통과한다.
- 홈과 로그인 화면이 데스크톱과 모바일 크기에서 정상 표시된다.
- 로그인하지 않은 사용자의 보호 페이지 접근은 로그인 화면으로 이동한다.
- 로그인하지 않은 `/api/questions` 요청은 `401`을 반환한다.
- 학생과 교사의 기존 로그인 흐름과 역할별 시작 화면이 유지된다.
- 질문 생성과 평가의 정상 응답, 대체 모델 재시도, 오류 변환이 기존 검사 계약을 만족한다.
- 빌드 결과에 Next.js 16에서 제거되거나 폐기 예정인 설정 경고가 남지 않는다.
- `npm audit --omit=dev` 결과에서 현재 Next.js 14 계열로 인한 운영 취약점이 제거된다. 남는 항목이 있다면 원인, 영향, 후속 조치를 커밋 설명에 기록한다.

## 완료 기준

다음 조건을 모두 만족하면 작업을 마친다.

1. 두 단계가 독립된 커밋으로 존재한다.
2. 모든 정적 검사, 단위 검사, 빌드, 주요 브라우저 흐름이 통과한다.
3. 데이터베이스 구조와 기존 행이 바뀌지 않았음을 확인한다.
4. 미리 보기 배포 확인 뒤 운영 배포가 성공한다.
5. 운영 배포 후 홈, 로그인, 비인증 API 경계를 다시 확인한다.
