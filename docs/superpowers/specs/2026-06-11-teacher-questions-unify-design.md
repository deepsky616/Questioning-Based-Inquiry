# 교사 질문조회 — 세션별/날짜-교과-주제별 조회 통합 설계

- 작성일: 2026-06-11
- 상태: 설계 승인됨 (목업 v2 확정)
- 대상 파일: `src/app/(teacher)/teacher-questions/page.tsx`

## 배경 / 문제

교사 질문조회는 두 조회 모드(`questionLookupMode: "session" | "detail"`)가 있다.
- **세션별**: 단일 세션 선택 → AI 세션 분석 · 학생 참여 현황 · 탐구설계 · 질문 목록 표시.
- **날짜-교과-주제별**: 여러 세션을 횡단 조회 → 질문 목록만 표시(AI 분석·참여·탐구설계 없음).

두 모드의 결과가 서로 달라 교사가 혼란스럽다. 통합해 **어떤 방식으로 골라도 같은 결과**가 나오게 한다.

## 핵심 결정 (승인됨)

**세션 고르기로 단일화** — 날짜·교과·주제는 세션을 좁히는 필터로만 쓰고, 결국 항상 **단일 세션**을 선택한다. 다중 세션 횡단 조회는 제거한다. 그러면 두 진입 방식이 동일한 단일 세션 결과로 수렴한다.

## 목표 / 비목표

### 목표
- `questionLookupMode` 토글 제거. 단일 조회 흐름.
- 날짜·교과·주제 필터(선택적) + 세션 선택으로 단일 세션 확정. `getSessionFilterOptions`/`filterSessions`(기존 `sessions.ts`) 재사용.
- 선택 세션 기준으로 화면을 위→아래 고정 순서로 표시:
  1. 학생 참여 현황
  2. AI 세션 분석
  3. 전체 질문 목록 (분류 통계 + 분류 탭 + 탐구설계 패널 + 질문들)
- 질문 목록에 **질문 분류 통계 현황**(분류1 폐쇄/개방, 분류2 사실/개념/논쟁의 개수·비율) 추가.
- 질문 중심 탐구설계 패널을 질문 목록 섹션 안으로 이동.

### 비목표
- 질문 분류 로직(closure/cognitive) 자체는 변경하지 않는다.
- AI 분석·참여 현황·탐구설계 각각의 내부 동작은 바꾸지 않는다(표시 조건만 단일화).
- 서버 API 변경 없음(단일 세션 질문 조회는 기존 `?sessionId=` 사용).

## UI 구조 (목업 v2 기준)

```
📋 질문조회
─ 🎯 수업 세션 선택   [날짜▼][교과▼][주제▼]  [세션▼]   ← 토글 없음, 필터+세션
─ 👥 학생 참여 현황    (전체/제출/미제출/참여율)
─ 🤖 AI 세션 분석      (요약·핵심주제·다음수업 제안)
─ 📝 전체 질문 목록
     ├ 📊 질문 분류 통계 현황   분류1: 폐쇄 n / 개방 m · 분류2: 사실/개념/논쟁
     ├ [분류1] 전체·폐쇄형·개방형   [분류2] 사실적·개념적·논쟁적   ← 탭 필터
     ├ ▸ 질문 중심 탐구설계 (묶기·순서·배포)  ← 접이식, 목록 안에 포함
     └ 질문 카드들
```

## 컴포넌트 / 데이터

### 세션 선택 (단일화)
- 상태에서 `questionLookupMode` 제거.
- 날짜/교과/주제 필터 상태(`filterDate`/`filterSubject`/`filterTopic`)는 유지하되, **세션을 좁히는 용도**로만 사용(질문을 직접 조회하지 않음).
- `filteredSessions = filterSessions(sessions, {date, subject, topic})`, 옵션은 `getSessionFilterOptions(sessions)`.
- `selectedSessionId`가 `filteredSessions`에 없으면 첫 세션으로 보정, 비면 선택 해제(student-ask와 동일 패턴).
- `currentSession`은 항상 `sessions.find(selectedSessionId)` (모드 분기 제거).
- 질문 로드는 단일 세션 기준: `fetch('/api/questions?sessionId=' + selectedSessionId)`.

### 질문 분류 통계 (신규 순수 함수)
- 위치: `src/lib/stats-calc.ts`(기존 통계 모듈) 또는 신규 헬퍼.
- `summarizeQuestionTypes(questions)` → `{ closure: {closed, open}, cognitive: {factual, conceptual, controversial}, total }`.
- 비율은 표시 단계에서 계산. 순수 함수라 단위 테스트.

### 표시 조건 단일화
- 기존 `questionLookupMode === "session" && currentSession` 조건들을 `currentSession`(있으면)으로 변경.
- `questionLookupMode === "detail"` 전용 블록(필터 폼, 테이블 "세션" 컬럼, 다중세션 질문 로드)은 제거.

## 제거 / 유지

| 대상 | 처리 |
|------|------|
| `questionLookupMode` 상태·토글 UI·모든 분기 | **제거** |
| detail 전용 필터 폼(날짜/교과/주제로 질문 직접 조회) | **세션 좁히기 필터로 대체** |
| 테이블 "세션" 컬럼(detail 전용) | **제거** |
| AI 세션 분석 · 학생 참여 현황 블록 | **유지**, 조건을 `currentSession`으로 단일화 + 순서(참여→AI) |
| 분류1/분류2 탭, 질문 테이블/카드 | **유지** |
| 질문 중심 탐구설계 패널 | **유지**, 질문 목록 섹션 안으로 이동 |
| 질문 분류 통계 현황 | **신규 추가** |

## 엣지 케이스
- 세션 0개: "표시할 세션이 없습니다" 안내, 결과 섹션 숨김.
- 필터 결과 0개: 세션 선택 비활성 + "조건에 맞는 세션이 없습니다".
- 질문 0개인 세션: 참여/AI/통계는 표시(0 기준), 질문 목록은 빈 상태.
- AI 분석 미실행: 기존 "분석하기" 버튼 동작 유지.

## 테스트 전략
- **단위(vitest)**: `summarizeQuestionTypes` 집계(폐쇄/개방, 사실/개념/논쟁, 빈 목록).
- **회귀**: 기존 teacher 관련 테스트 통과. 타입체크·빌드 성공.
- **수동 확인**: 날짜/교과/주제로 좁힌 결과와 세션 직접 선택 결과가 동일.

## 점진적 구현 순서(요약)
1. `summarizeQuestionTypes` 순수 함수 + 테스트.
2. 세션 선택 단일화(토글 제거, 필터+세션, currentSession 통일, 단일 세션 질문 로드).
3. 결과 섹션 순서(참여→AI) + 표시 조건 단일화.
4. 질문 목록에 분류 통계 현황 추가.
5. 탐구설계 패널을 질문 목록 섹션 안으로 이동.
6. detail 잔재(필터 폼·세션 컬럼·분기) 제거 + 빌드·회귀 확인.

> 상세 단계·파일별 변경은 구현 계획(plan)에서 다룬다.
