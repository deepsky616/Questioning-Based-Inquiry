# 역할별 질문학습 흐름과 연습 진단 설계

## 배경

학생과 교사는 현재 같은 14장 질문학습 자료를 본다. 공통 자료는 질문 유형의 정의와 예시를 한곳에서 관리하므로 내용이 서로 어긋나지 않는 장점이 있다. 그러나 학습 마지막 장은 다음 행동을 안내하는 문장만 보여 주고, 질문연습에서 성공한 질문도 실제 질문하기로 이어지지 않는다.

질문연습 서버는 학생의 정답과 오답을 `PracticeAttempt`에 모두 기록한다. 반면 학생 화면의 정답 수는 새로 고침하면 사라지고, 교사 현황은 포인트 지급 기록을 바탕으로 성공 횟수만 보여 준다. 이미 쌓이는 시도 자료를 활용하면 새 데이터 표 없이도 학생 취약 유형과 학급 오개념을 보여 줄 수 있다.

이번 개선은 다음 두 단계를 순서대로 완성한다.

1. 질문학습에서 질문연습을 거쳐 실제 질문하기로 이어지는 흐름
2. 기존 정답·오답 기록을 이용한 학생 맞춤 진단과 교사 학급 진단

## 목표

1. 공통 14장 질문학습 자료는 하나로 유지한다.
2. 학생 질문학습은 학습, 연습, 실제 질문 작성으로 이어진다.
3. 교사 질문학습은 같은 핵심 자료에 수업 활용 관점을 더한다.
4. 학생이 연습에서 만든 질문을 다시 입력하지 않고 실제 질문하기로 옮긴다.
5. 실제 질문 분석 뒤 원문과 피드백을 유지하면서 다시 쓸 수 있다.
6. 기존 `PracticeAttempt`로 학생 개인과 담당 학급의 학습 상태를 진단한다.
7. 첫 구현에서는 데이터베이스 구조와 기존 자료를 바꾸지 않는다.

## 제외 범위

- 권한 경계 전면 보완
- 교사가 학생에게 연습 과제를 배정하는 기능
- 질문학습 진행 위치를 여러 기기에서 동기화하는 기능
- 새 포인트 규칙이나 기존 포인트 재계산
- 14장 핵심 학습 자료의 정의와 순서 변경
- 인공지능 실시간 출제 기록의 세부 유형을 추측해서 진단하는 기능
- 학생 순위와 학생 사이 비교

## 설계 원칙

### 핵심 학습 자료는 공통으로 유지

사실적·개념적·논쟁적 질문과 열린·닫힌 질문의 정의, 공식, 예시는 학생과 교사에게 동일해야 한다. 학생용과 교사용 슬라이드를 별도 파일로 복사하지 않는다.

`QuestionDetectiveSlides`와 `QuestionLearningSlideContent`는 공통 학습 자료와 이동을 계속 담당한다. 역할에 따른 차이는 완료 행동과 교사용 활용 자료처럼 공통 본문 바깥의 얇은 계층으로 둔다.

### 학생과 교사의 다음 행동을 다르게 구성

학생은 배운 내용을 직접 사용해야 한다. 학생 질문학습의 마지막 장에는 `질문연습 시작`을 기본 행동으로 제공한다. 연습에서 목표를 달성하면 실제 질문하기로 질문 초안을 보낼 수 있다.

교사는 같은 자료를 먼저 학습하고 수업에서 어떻게 사용할지 확인해야 한다. 교사 질문학습은 다음 두 보기를 제공한다.

- `학습 내용`: 학생과 같은 14장 슬라이드
- `수업 활용`: 핵심 장별 학습 목표, 학생이 자주 혼동하는 점, 수업 발문, 이어서 물을 질문

교사 학습 완료 행동은 `직접 연습하기`와 `수업 활용 보기`다. 교사에게 학생의 실제 질문하기 이동은 제공하지 않는다.

### 진단은 활동량보다 학습 상태를 보여 줌

포인트는 동기 부여 자료이지 정확한 숙달 자료가 아니다. 진단은 정답과 오답이 모두 있는 `PracticeAttempt`를 기준으로 한다.

- 학생 화면은 자신의 최근 시도, 정답률, 약한 축과 추천 연습만 보여 준다.
- 교사 화면은 담당 학생의 시도 수, 정답률, 약한 축과 학급에서 자주 틀린 유형을 보여 준다.
- 포인트는 기존 보조 정보로 유지한다.
- 시도 수가 적을 때는 취약 유형으로 단정하지 않고 `진단 자료를 모으는 중`으로 표시한다.

## 1단계: 학습, 연습, 질문하기 연결

### 역할별 학습 화면

`QuestionLearningExperience`는 역할을 입력으로 받아 역할별 완료 행동을 조합한다.

학생 경로 `/student-question-learning`:

- 공통 14장 학습 자료
- 마지막 장의 `질문연습 시작`
- 학생 질문연습 `/student-practice`로 이동

교사 경로 `/teacher-question-learning`:

- `학습 내용`, `수업 활용` 두 보기
- 학습 내용에는 공통 14장 자료
- 마지막 장의 `직접 연습하기`, `수업 활용 보기`
- 직접 연습하기는 `/teacher-practice`의 직접 해보기로 이동
- 수업 활용 보기는 같은 페이지 안의 교사용 활용 자료로 이동하고 제목에 초점을 둔다.

공통 슬라이드에 역할별 경로를 직접 넣지 않는다. 마지막 장이 받을 완료 행동을 공통 경험이 주입하는 방식으로 역할 의존성을 분리한다.

### 교사용 수업 활용 자료

교사용 자료는 전체 슬라이드를 다시 복사하지 않는다. 다음 핵심 주제에 대응하는 짧은 활용 항목을 별도 자료 파일에서 관리한다.

1. 질문의 두 분류 축
2. 열린 질문과 닫힌 질문
3. 사실적 질문
4. 개념적 질문
5. 논쟁적 질문
6. 세 유형 비교와 즉석 확인

각 항목의 교육 내용은 다음 네 필드만 갖는다. 화면에서 항목을 구분하고 학생 현황 필터를 만드는 `id`, `title`, `focus`는 내용과 분리된 표시용 메타자료로 둔다.

- 학습 목표
- 자주 생기는 혼동
- 수업에서 먼저 물을 질문
- 학생 답변 뒤 이어서 물을 질문

최종 문구는 다음과 같다.

#### 질문의 두 분류 축

- 학습 목표: 답의 범위와 답에 필요한 사고를 서로 다른 기준으로 분류한다.
- 자주 생기는 혼동: 사실적 질문은 항상 닫혀 있고 논쟁적 질문은 항상 열려 있다고 생각한다. 질문의 첫 낱말만 보고 유형을 정한다.
- 수업에서 먼저 물을 질문: `이 질문은 답의 범위와 답에 필요한 사고를 각각 어떻게 분류할 수 있을까요?`
- 학생 답변 뒤 이어서 물을 질문: `두 기준 가운데 하나만 바꾸려면 질문과 근거가 어떻게 달라져야 할까요?`

#### 열린 질문과 닫힌 질문

- 학습 목표: 받아들일 수 있는 답의 범위를 판단하고 사고의 깊이와 분리한다.
- 자주 생기는 혼동: `왜`, `어떻게`가 있으면 모두 열린 질문이라고 생각한다. 닫힌 질문은 언제나 단순하다고 생각한다.
- 수업에서 먼저 물을 질문: `이 질문의 답은 자료에서 하나로 확인되나요, 여러 근거 있는 답이 가능한가요?`
- 학생 답변 뒤 이어서 물을 질문: `답이 여러 개라면 아무 답이나 가능한가요? 좋은 답에 필요한 근거는 무엇인가요?`

#### 사실적 질문

- 학습 목표: 기억, 관찰, 조사, 계산이나 정해진 절차로 확인할 정보를 묻는다.
- 자주 생기는 혼동: 사실적 질문은 답이 반드시 하나라고 생각한다. `어떻게`와 `왜`가 들어가면 사실적 질문이 아니라고 생각한다.
- 수업에서 먼저 물을 질문: `이 질문에 답하려면 어떤 자료, 관찰, 계산이나 절차가 필요한가요?`
- 학생 답변 뒤 이어서 물을 질문: `답을 확인한 사람이 같은 방법으로 다시 확인할 수 있나요?`

#### 개념적 질문

- 학습 목표: 여러 사실을 연결해 관계, 원리, 의미와 영향을 설명한다.
- 자주 생기는 혼동: `왜`가 들어간 모든 질문을 개념적 질문으로 분류한다. 근거 없는 느낌이나 의견도 개념적 설명이라고 생각한다.
- 수업에서 먼저 물을 질문: `따로 알고 있는 어떤 사실들을 연결해야 이 질문에 답할 수 있나요?`
- 학생 답변 뒤 이어서 물을 질문: `한 사실만 외워서 답할 수 있나요? 어떤 관계를 설명해야 하나요?`

#### 논쟁적 질문

- 학습 목표: 충돌하는 가치, 선택과 책임을 근거로 비교해 판단한다.
- 자주 생기는 혼동: 사람마다 답이 다르면 모두 논쟁적 질문이라고 생각한다. 토론을 상대를 이기는 활동으로 생각한다.
- 수업에서 먼저 물을 질문: `이 선택에서 서로 부딪히는 가치와 책임은 무엇인가요?`
- 학생 답변 뒤 이어서 물을 질문: `반대 입장에서 가장 강한 근거는 무엇이며, 어떤 조건에서 판단이 달라질 수 있나요?`

#### 세 유형 비교와 즉석 확인

- 학습 목표: 같은 질문 낱말을 써도 필요한 사고와 근거에 따라 유형이 달라짐을 설명한다.
- 자주 생기는 혼동: 대표 낱말 목록을 정답표처럼 외우고 질문 전체가 요구하는 사고를 보지 않는다.
- 수업에서 먼저 물을 질문: `세 질문이 모두 어떻게로 시작해도 서로 다른 유형인 까닭은 무엇인가요?`
- 학생 답변 뒤 이어서 물을 질문: `한 질문을 다른 유형으로 바꾸려면 답에 필요한 사고와 근거를 어떻게 바꿔야 하나요?`

교사용 활용 화면은 읽기 전용이며 학생 자료, 포인트와 문항 은행을 바꾸지 않는다. 전체 슬라이드가 필요한 때는 `학습 내용` 보기를 학생용 발표 화면으로 사용한다.

### 연습 질문 초안 전달

질문 바꾸기와 질문 만들기에서 목표를 달성한 학생에게 `이 질문으로 질문하기`를 제공한다. 분류 퀴즈는 학생이 만든 질문이 없으므로 이 행동을 표시하지 않는다.

질문 본문을 주소에 넣지 않는다. 브라우저의 같은 탭에서만 쓰는 버전이 붙은 임시 저장값으로 전달한다.

임시 저장값은 다음 정보를 가진다.

- 형식 버전
- 작성 학생 식별값
- 질문 본문
- 연습 종류
- 목표 유형
- 생성 시각

규칙은 다음과 같다.

- 질문은 앞뒤 공백을 없애고 200자로 제한한다.
- 저장 키는 학생 식별값을 포함하고, 저장값의 작성 학생 식별값도 현재 로그인 학생과 대조한다.
- 저장 뒤 `/student-ask?draft=practice`로 이동한다.
- 질문하기 화면은 작성 학생, 값의 형식, 길이와 생성 시각을 확인한 뒤 한 번만 읽고 바로 지운다.
- 다른 학생으로 로그인한 경우 이전 학생 키를 읽지 않으며, 우연히 잘못된 키가 전달돼도 작성 학생이 다르면 폐기한다.
- 값이 없거나 잘못됐거나 생성 뒤 30분이 지났으면 조용히 무시한다.
- 기존 질문, 수업 세션, 포인트와 연습 기록은 수정하지 않는다.
- 학생이 수업 세션을 고른 뒤 초안을 분석하고 저장하는 기존 절차는 그대로 유지한다.

### 피드백을 유지하는 다시 쓰기

현재 `다시 쓰기`는 분석 결과와 입력 질문을 모두 지운다. 이를 다음과 같이 바꾼다.

- 입력 질문은 유지한다.
- 분석 결과의 유형, 이유, 피드백과 개선 예시는 입력 옆에 남긴다.
- 입력창으로 초점을 옮기고 전체 선택은 하지 않는다.
- 학생이 수정한 뒤 `다시 분석`을 실행한다.
- 개선 예시가 있을 때 `예시를 초안으로 사용`을 제공하되 학생이 직접 눌렀을 때만 질문을 바꾼다.
- 아직 저장하지 않은 분석 결과만 비교하며 새 데이터는 저장하지 않는다.
- 질문 저장이 끝난 뒤 `같은 수업에 새 질문 쓰기`는 기존처럼 빈 질문으로 시작한다.

분석 결과는 분석 당시 질문 본문과 한 묶음으로 보관한다. 현재 입력이 분석 당시 본문과 다르면 이전 결과는 참고용으로만 표시하고 저장 행동을 막으며 `다시 분석`을 기본 행동으로 바꾼다. 서버 저장 직전에도 현재 입력과 마지막 분석 본문이 같은지 확인한다. 따라서 수정한 질문이 예전 분류 결과로 저장되지 않는다.

수정 전 질문은 화면 상태에만 보관한다. 다시 분석한 뒤에는 이전 질문과 현재 질문을 나란히 길게 표시하지 않고, 바뀐 문장과 새 판정이 보이도록 짧은 `수정 전 질문` 접기 영역을 제공한다.

## 2단계: 학생과 교사 진단

### 진단 자료 범위

첫 구현은 기존 `PracticeAttempt`만 읽는다. 새 열이나 새 표를 만들지 않는다.

세부 유형을 정확하게 알 수 있는 기록:

- 내장 분류 퀴즈: `itemId`, `quizType`과 고정된 내장 문항 자료로 실제로 물어본 축의 유형 하나만 찾는다. `quizType=closure`이면 닫힌·열린 진단에만 반영하고, `quizType=cognitive`이면 사실적·개념적·논쟁적 진단에만 반영한다. 한 번의 정오를 두 축에 동시에 넣지 않는다.
- 내장 질문 바꾸기: `itemId`와 고정된 문항 목표로 열린·개념적·논쟁적 목표를 찾는다.

세부 유형을 알 수 없는 기록:

- 교사 문항은 수정과 삭제가 가능하며 시도 행에 당시 유형 사본이 없으므로 유형별 진단에서 제외한다.
- 학생이 목표 유형을 고르는 질문 만들기 기록은 현재 시도 행에 선택 목표가 없다.
- 인공지능 실시간 출제 기록은 `itemId`가 없다.

이 기록은 전체 시도와 모드별 정답률에는 포함하지만 유형별 취약 진단에서는 제외한다. 세부 유형을 추측하지 않는다.

### 집계 기간과 반복 시도

학생과 교사 진단은 모두 최근 30일을 사용한다. 학생 한 명당 가장 최근 100개까지만 분석하고, 응답에는 100개 상한에 도달했는지 함께 표시한다.

반복 풀이가 숙달 판단을 과도하게 바꾸지 않도록 두 수치를 구분한다.

- 활동 시도 수: 최근 기록 가운데 분석한 모든 시도 수
- 진단 시도 수: 같은 학생이 같은 날짜에 같은 모드, 문항과 퀴즈 축을 여러 번 풀었으면 가장 최근 결과 하나만 사용한 수

날짜 경계는 서비스의 포인트 날짜와 같은 서울 시간대를 사용한다. 인공지능 실시간 출제처럼 문항 식별값이 없는 기록은 같은 날짜와 같은 모드에서 가장 최근 결과 하나만 전체 및 모드 진단에 사용하고 유형별 진단에서는 제외한다.

교사 조회도 학생마다 최근 100개를 공평하게 가져온다. 한 학생의 많은 시도가 다른 학생 자료를 밀어내지 않도록 학생 식별값으로 나눈 뒤 최근 순번 100개를 고르는 한 번의 묶음 조회를 사용한다. 담당 학생 전체의 무제한 시도를 메모리로 읽지 않는다.

### 학생 개인 진단

새 학생용 조회 경로는 로그인한 학생 자신의 최근 시도만 반환한다. 기본 기간은 최근 30일이고 가장 최근 100개를 상한으로 둔다.

응답은 다음을 제공한다.

- 활동 시도 수
- 진단 시도 수와 정답 수
- 진단 정답률
- 분류, 바꾸기, 만들기 모드별 진단 시도 수와 정답률
- 답의 범위 축 정답률
- 사실적·개념적·논쟁적 사고 유형별 정답률
- 진단에서 제외된 세부 유형 미확인 시도 수
- 최근 100개 상한 도달 여부
- 추천할 다음 연습 하나

추천 규칙은 서버의 결정적 함수로 둔다.

1. 진단 대상은 닫힌, 열린, 사실적, 개념적, 논쟁적 다섯 유형이다.
2. 한 유형의 취약 여부는 그 유형의 진단 시도가 3개 이상일 때만 판단한다.
3. 아직 시도 3개를 채운 유형이 하나도 없으면 유형을 고정하지 않은 분류 연습을 추천한다.
4. 시도 3개를 채우지 못한 유형이 있으면 그 유형을 먼저 연습하도록 추천해 진단 자료를 채운다.
5. 다섯 유형이 모두 3개 이상이면 정답률이 가장 낮은 유형을 추천한다.
6. 같은 정답률이면 최근 오답이 있는 유형을 먼저 추천하고, 그래도 같으면 닫힌, 열린, 사실적, 개념적, 논쟁적 순서로 결정한다.
7. 다섯 유형의 정답률이 모두 80퍼센트 이상이면 질문 바꾸기를 추천한다.

학생 질문연습 위쪽에는 조용한 진단 띠를 둔다. 큰 성과 카드나 순위표를 만들지 않는다. 자료가 없으면 `몇 문제 풀면 맞춤 추천이 시작돼요`와 분류 연습 시작 행동만 보여 준다.

추천 행동의 정확한 이동은 다음과 같다.

| 추천 | 연습 보기 | 축 | 문항 제한 |
| --- | --- | --- | --- |
| 자료 모으기 | 분류 | 사고 유형 | 제한 없음 |
| 닫힌 질문 | 분류 | 답의 범위 | 닫힌 질문 문항 |
| 열린 질문 | 분류 | 답의 범위 | 열린 질문 문항 |
| 사실적 질문 | 분류 | 사고 유형 | 사실적 질문 문항 |
| 개념적 질문 | 분류 | 사고 유형 | 개념적 질문 문항 |
| 논쟁적 질문 | 분류 | 사고 유형 | 논쟁적 질문 문항 |
| 다섯 유형 숙달 | 질문 바꾸기 | 해당 없음 | 기존 섞인 문항 |

질문연습은 허용된 추천 매개값을 읽어 분류 축과 문항 묶음을 선택한다. 제한된 문항 묶음이 비어 있으면 전체 분류 문항으로 돌아간다. 잘못된 주소 매개값은 기본 분류 보기로 돌린다. 질문 만들기에는 사실적 목표가 없으므로 첫 추천 행동으로 직접 연결하지 않는다.

### 교사 학급 진단

기존 `/api/teacher/practice-stats`는 포인트 기록뿐 아니라 담당 학생의 `PracticeAttempt`를 함께 집계한다.

교사 화면은 다음을 제공한다.

- 학급 전체 활동 시도 수, 진단 시도 수와 정답률
- 답의 범위 축과 세 사고 유형의 정답률
- 가장 많이 틀린 유형과 최소 표본 수
- 학생별 최근 활동 시도 수, 진단 시도 수, 정답률, 약한 유형과 상한 도달 여부
- 오늘과 최근 7일 포인트는 기존 보조 열로 유지

담당 학급 규칙은 기존 학생 목록과 같은 학교, 학년, 반 범위를 그대로 사용한다. 담당 학생이 아닌 자료를 포함하지 않는다.

학생 행을 누르면 새 대화창을 만들지 않고 같은 화면 안에서 세부 행을 펼친다. 세부 행은 모드별 시도와 유형별 정답률만 보여 준다. 과제 배정과 학생 자료 수정은 하지 않는다.

정답률은 시도 수와 함께 표시한다. 시도 1회의 0퍼센트와 충분한 시도의 0퍼센트를 같은 의미로 보이게 하지 않는다.

### 교사 질문학습과 진단 연결

교사 질문학습의 `수업 활용` 보기에서 각 유형은 `학생 현황에서 이 유형 보기` 행동을 가질 수 있다. 이 행동은 교사 질문연습의 학생 현황으로 이동하면서 유형 필터만 전달한다.

필터는 화면 표시만 바꾸며 자료를 수정하지 않는다. 해당 유형의 표본이 없으면 빈 표 대신 아직 시도가 없다는 안내를 보여 준다. 이어서 해당 유형의 내장 분류 연습을 교사가 미리 보거나, 같은 학생용 연습 주소를 복사해 학급에 안내할 수 있다. 이 주소는 학생 질문연습에서 분류 축과 내장 문항 제한만 적용하며 과제를 만들거나 학생 자료를 수정하지 않는다.

`문항 은행 관리`는 별도 보조 행동으로 유지할 수 있지만, 교사 문항 시도는 유형별 진단에서 제외되므로 표본을 채우는 행동으로 설명하지 않는다.

## 오류 처리

- 임시 초안 저장을 사용할 수 없으면 질문 본문을 지우지 않고 같은 화면에 오류를 알린다.
- 진단 조회 실패는 연습 기능을 막지 않는다. 진단 영역에 다시 시도 행동을 제공한다.
- 교사 현황 조회 실패를 빈 학생 목록으로 보이지 않는다.
- 알 수 없는 문항 식별값은 전체 통계에 포함하고 세부 유형에서 제외한다.
- 나누기 기준이 0이면 정답률은 `null`로 반환하고 화면에는 자료 없음으로 표시한다.
- 모든 조회 기간과 반환 개수에 상한을 둔다.

## 접근성 및 반응형 설계

- 역할별 보기는 탭 역할, 선택 상태, 연결된 패널 이름을 갖는다.
- 수업 활용 보기로 이동하면 제목에 프로그램 초점을 옮긴다.
- 임시 초안이 질문하기에 들어오면 입력창 설명을 실시간 안내로 한 번 알린다.
- 다시 쓰기는 입력창으로 초점을 돌린다.
- 진단은 색만으로 상태를 구분하지 않고 유형명, 시도 수와 정답률을 함께 쓴다.
- 학생과 교사 진단 표는 작은 화면에서 가로 표 대신 학생 또는 유형별 세로 행으로 바뀐다.
- 펼침 학생 행은 단추로 동작하고 열림 상태를 알린다.
- 움직임 감소 설정에서 펼침과 탭 전환 애니메이션을 없앤다.

## 구성요소와 자료 경계

예상 경계는 다음과 같다.

- `QuestionLearningExperience`: 역할별 보기와 완료 행동 조합
- `QuestionDetectiveSlides`: 공통 14장 이동과 완료 행동 표시
- `TeacherQuestionLearningGuide`: 교사용 수업 활용 보기
- `question-teaching-guide-data`: 교사용 활용 자료의 단일 원본
- `QuestionPracticeView`: 역할별 성공 행동과 추천 탭 적용
- `practice-draft`: 임시 질문 초안 검증, 저장, 읽기와 삭제
- `PracticeProgressSummary`: 학생 개인 진단 띠
- `practice-diagnostics`: 시도 자료를 정답률과 추천으로 바꾸는 순수 함수
- 학생 개인 진단 조회 경로
- 기존 교사 연습 현황 조회 경로 확장

페이지는 역할과 이동 경로만 넘긴다. 공통 연습 보기가 현재 주소를 읽어 역할을 추측하지 않는다.

## 자료 영향

### 1단계

- 데이터베이스 구조 변경 없음
- API 변경 없음
- 기존 질문, 포인트, 연습 시도와 교사 문항 변경 없음
- 질문 초안은 같은 브라우저 탭의 임시 저장소에만 잠시 존재하고 한 번 읽은 뒤 삭제

### 2단계

- 데이터베이스 구조 변경 없음
- 기존 `PracticeAttempt`, 내장 문항과 교사 문항을 읽기만 함
- 기존 교사 연습 현황 응답에 진단 필드를 추가
- 학생 개인 진단 조회 경로 추가
- 기존 포인트와 정답·오답 기록 방식 변경 없음

응답 필드 추가는 기존 화면이 사용하던 필드를 유지하는 하위 호환 방식으로 한다.

## 시험 설계

### 1단계

1. 학생과 교사가 같은 14장 핵심 자료를 사용한다.
2. 학생 마지막 장에는 학생 질문연습 이동만 있다.
3. 교사 마지막 장에는 직접 연습과 수업 활용 행동이 있다.
4. 교사 수업 활용 보기는 여섯 핵심 주제와 설계에 확정한 네 필드 문구를 그대로 가진다.
5. 학생 연습 성공 때만 실제 질문하기 행동이 보인다.
6. 교사 직접 연습에는 실제 질문하기 행동이 없다.
7. 분류 퀴즈에는 질문 초안 전달 행동이 없다.
8. 임시 초안은 작성 학생, 200자, 형식 버전과 30분 유효 시간을 검증한다.
9. 질문하기는 현재 학생의 유효한 초안을 한 번 읽고 삭제한다.
10. 다른 학생, 잘못된 값이나 오래된 초안은 기존 빈 입력 흐름을 바꾸지 않는다.
11. 다시 쓰기는 원문과 피드백을 유지하고 입력창에 초점을 돌린다.
12. 개선 예시는 학생 행동이 있을 때만 입력을 바꾼다.
13. 현재 질문이 마지막 분석 본문과 다르면 예전 결과로 저장할 수 없다.
14. 학생 학습, 연습, 질문하기 전체 흐름을 실제 브라우저에서 확인한다.
15. 교사 학습 내용과 수업 활용 전환을 실제 브라우저에서 확인한다.

### 2단계

1. 진단 순수 함수가 0건, 적은 표본, 동률, 충분한 숙달을 처리한다.
2. 활동 통계는 세부 유형을 모르는 기록도 포함한다.
3. 유형별 통계는 고정된 내장 문항 기록만 포함하고 교사 문항과 인공지능 문항은 제외한다.
4. 답의 범위 퀴즈 정오는 닫힌·열린 축에만, 사고 유형 퀴즈 정오는 사실적·개념적·논쟁적 축에만 반영한다.
5. 같은 날짜의 같은 문항 반복 시도는 가장 최근 결과 하나만 진단에 반영한다.
6. 학생 조회는 본인 자료만 최근 30일, 최대 100개까지 읽고 상한 도달 여부를 알린다.
7. 교사 조회는 담당 학생마다 최근 30일, 최대 100개를 공평하게 읽는다.
8. 기존 포인트 필드가 응답에서 유지된다.
9. 학생 진단 띠가 자료 없음, 불러오는 중, 실패, 진단 완료 상태를 구분한다.
10. 일곱 추천 결과가 설계 표의 연습 보기, 축과 문항 제한을 정확히 선택한다.
11. 제한된 문항이 없거나 주소 매개값이 잘못되면 전체 분류 문항으로 돌아간다.
12. 교사 화면이 학급 요약과 학생별 시도 수, 정답률, 약한 유형을 표시한다.
13. 표본 없음 행동은 해당 내장 연습 미리보기와 학생용 연습 주소를 제공하며 문항 은행이 표본을 만든다고 안내하지 않는다.
14. 작은 화면에서 진단 내용이 잘리거나 가로로 넘치지 않는다.
15. 학생과 교사 진단 경로의 단위 시험과 브라우저 시험을 추가한다.

## 단계별 구현 순서

1. 역할별 질문학습 완료 행동과 교사용 수업 활용 보기
2. 학생 연습 질문의 임시 초안 전달
3. 피드백을 유지하는 실제 질문 다시 쓰기
4. 진단 집계 순수 함수와 학생 개인 조회
5. 학생 맞춤 진단 띠와 추천 이동
6. 교사 현황 조회 확장과 학급 진단 화면
7. 교사 수업 활용에서 유형별 학생 현황으로 이동
8. 전체 단위 시험, 린트, 형 검사, 운영 빌드와 역할별 브라우저 시험

각 단계는 독립 커밋과 검토를 거친다. 1단계 전체 검증이 끝난 뒤 2단계를 시작한다.

## 완료 기준

1. 학생은 질문학습 마지막 장에서 질문연습으로 이동할 수 있다.
2. 학생은 연습에서 만든 질문을 실제 질문하기 입력으로 한 번 전달할 수 있다.
3. 학생은 분석 피드백을 보면서 원문을 수정하고 다시 분석할 수 있다.
4. 교사는 공통 학습 자료와 별도의 수업 활용 보기를 사용할 수 있다.
5. 학생은 자신의 최근 정답률, 약한 유형과 추천 연습을 볼 수 있다.
6. 교사는 담당 학급과 학생별 시도 수, 정답률과 약한 유형을 볼 수 있다.
7. 첫 구현에서 데이터베이스 구조와 기존 자료가 바뀌지 않는다.
8. 전체 시험, 린트, 형 검사와 운영 빌드가 통과한다.
9. 학생·교사 핵심 흐름의 실제 브라우저 시험이 통과한다.
10. 변경을 단계별로 커밋하고 원격 `main`에 푸시한다.
