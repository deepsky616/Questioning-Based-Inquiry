# 질문놀이 포인트 복구 설계

## 목표

서버가 확인한 질문놀이 활동에만 포인트를 지급하되, 방장 역할이나 결과 화면 체류 여부 때문에 정상 완료한 학생의 포인트가 빠지지 않게 한다. 친구 방을 먼저 복구하고, 혼자 및 도움 모드는 서버 실행 기록이 준비된 놀이부터 차례로 연결한다.

## 확인한 문제

- 버전 2 친구 방은 점수 근거가 서버에 있지만 교사 방장만 지급 경로를 호출할 수 있다.
- 학생 방장은 실제 학생이어도 지급 대상에서 제외된다.
- 교사 방도 교사가 결과 화면을 떠나면 지급을 시작할 주체가 없다.
- 혼자 및 도움 모드는 화면의 완료값을 믿지 않도록 막은 뒤 서버 실행 기록으로 대체되지 않았다.
- 2026년 7월 14일 뒤 버전 2 질문놀이 포인트 기록은 만들어지지 않았다.

## 친구 방 지급

버전 2 방이 `ended`, `done`, `completed`가 된 뒤 서버가 저장된 방을 다시 읽어 포인트를 보장한다. 마지막 명령 처리 직후 자동으로 시도하고, 결과 화면의 인증 참가자도 같은 보장 경로를 다시 호출할 수 있다. 두 경로는 같은 실행 키와 거래 잠금을 사용하므로 실제 지급은 한 번만 일어난다.

지급 대상은 완료 순간 참가자 자료의 식별값을 사용자 표에서 다시 조회해 역할이 `STUDENT`인 사람으로 정한다. 학생 방장을 포함하고 교사 참가자는 제외한다. 요청자가 보낸 참가자, 질문 수, 점수, 우승값은 사용하지 않는다.

정상 완료가 아닌 방장 종료와 참가자 부족 종료에는 지급하지 않는다. 기존 방과 이전 점수는 옮기거나 다시 계산하지 않는다. 점수 분석 호출이 실패해도 참여, 서버 검증 활동, 완료, 우승 기본 포인트는 지급한다.

친구 방 하루 상한은 학생당 120점으로 둔다. 완료 시각을 서울 날짜로 바꿔 같은 날짜의 승인된 친구 방 기록을 합산하고 남은 범위 안에서만 지급한다. 실행별 고유키, 자문 잠금, 직렬 거래, 점수 기록 고유 제약을 함께 유지한다.

## 혼자 및 도움 모드

클라이언트가 보낸 완료 여부와 활동 수만으로 포인트를 다시 열지 않는다. 기존 신뢰 기록 설계의 `GameRun`과 `GameActivity`를 추가 전용 자료로 만들고, 서버가 시작, 활동, 완료 순서를 검증한 실행만 지급한다.

공통 기반은 실행 생성, 요청 재전송 식별값, 낙관적 버전, 활동 한도, 완료 거래, 결과 조회를 맡는다. 일곱 놀이는 친구 방에서 사용하는 서버 규칙 처리기를 재사용할 수 있는 순서대로 세로 단위로 옮긴다. 준비되지 않은 놀이는 계속 미지급 상태를 명확히 표시한다.

혼자 모드는 하루 30점, 도움 모드는 하루 50점 상한을 유지한다. 인공지능 동작은 진행에는 포함해도 학생 활동 점수에는 포함하지 않는다.

## 시험 기준

- 학생 방장과 학생 참가자가 각자의 서버 검증 활동에 맞는 포인트를 받는다.
- 교사 방장은 포인트 대상에서 빠지고 담당 학생은 지급받는다.
- 같은 완료 요청을 순서대로 또는 동시에 여러 번 보내도 총점과 기록은 한 번만 늘어난다.
- 비정상 종료, 완료 전 상태, 바뀐 실행 식별값은 지급되지 않는다.
- 점수 분석 실패 뒤에도 기본 포인트가 지급된다.
- 결과 화면을 닫았다 다시 열어도 미지급 실행을 복구하고 같은 결과를 보여 준다.
- 혼자 및 도움 모드는 서버 실행 없이 보낸 완료 요청을 계속 거절한다.
- 기존 사용자, 질문, 수업, 포인트 기록은 그대로 유지된다.
