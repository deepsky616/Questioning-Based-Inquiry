# 자료 접근 경계 보완 설계

## 목표

교사와 학생이 학교, 담당 학급, 질문수업 배정 범위를 벗어난 자료를 읽거나 바꾸지 못하게 한다. 기존 자료와 표 구조는 변경하지 않는다.

## 공통 규칙

- 교사 자료가 없거나 학교가 비어 있으면 학생 자료 접근을 허용하지 않는다.
- 교사에게 담당 학급이 있으면 같은 학교의 해당 학년과 반 학생만 허용한다.
- 담당 학급이 없으면 현재 제품 규칙을 유지해 같은 학교 학생 조회와 점수 관리를 허용한다.
- 학생은 자기 비공개 질문을 볼 수 있지만 다른 작성자의 비공개 질문은 볼 수 없다.
- 학생은 같은 학교에서 자신을 담당하는 교사의 활성 질문수업 가운데 대상 조건에 맞는 수업에만 질문을 낼 수 있다.
- 학생의 질문 목록, 질문 상세, 댓글, 좋아요, 번역, 배포 질문, 참고자료도 같은 질문수업 대상 조건을 따른다.
- 교사는 자신이 만든 질문수업에만 질문을 낼 수 있다.
- 알 수 없는 역할과 불완전한 학급 대상 자료는 허용하지 않는다.
- 공개 주소에서는 학생 계정을 만들지 않고, 교사 가입은 서버 가입 코드가 맞을 때만 허용한다.
- 질문놀이 방 전체 자료는 참가자만 읽고, 전체 상태 교체와 종료 상태 변경은 방장만 수행한다.
- 멀티 질문놀이 점수는 교사 방장이 담당 학생의 서버 저장 활동을 확인한 경우만 지급한다.
- 서버에서 완료를 확인할 수 없는 단독 질문놀이 점수는 기록하지 않는다.
- 접근이 불분명하면 허용하지 않는다.

## 적용 범위

1. 단일 학생 보고서와 학급 보고서에 학교 및 담당 학급 검사를 적용한다.
2. 교사 수동 점수 변경 대상이 관리 범위 안의 학생인지 확인한다.
3. 교사 질문 목록에는 학교 조건을 항상 포함한다.
4. 학생 질문 목록에는 자기 질문 또는 허용 범위의 공개 질문 조건을 서버에서 강제한다.
5. 질문 작성 전에 질문수업 소유자, 학교, 담당 학급, 대상 학생, 활성 상태를 확인한다.
6. 학생 질문수업 목록에서 다른 학교 교사의 수업을 제외한다.
7. 질문수업 생성과 수정, 탐구설계 배포에서 학급과 학생 대상이 교사 범위 안인지 확인한다.
8. 학생별 분석과 저장된 분석 수정, 묶음 분석에서 수업 소유와 실제 배정 대상을 확인한다.
9. 포인트 조회와 승인에서 교사 소유 수업 및 현재 담당 학생 범위를 함께 확인한다.
10. 같은 대기 포인트를 동시에 승인해도 총점은 한 번만 반영한다.
11. 담당 학급이 없는 교사의 같은 학교 학급 목록을 실제 학생 자료에서 구성한다.
12. 공개 학생 가입을 차단하고 교사 가입에 서버 가입 코드를 요구한다.
13. 학생 생성, 질문놀이 통계, 순위 조회에 교사 학교와 담당 학급 범위를 적용한다.
14. 학생 질문놀이와 순위 조회는 요청값이 아니라 데이터베이스의 본인 소속을 사용한다.
15. 질문놀이 방 읽기와 상태 쓰기에 참가자, 방장, 상태 버전 검사를 적용한다.
16. 질문놀이 점수는 요청의 학생 번호와 점수를 버리고 교사 범위와 저장 활동으로 다시 계산한다.

## 오류 처리

- 로그인이 없으면 `401`을 반환한다.
- 역할이 맞지 않거나 범위를 벗어나면 `403`을 반환한다.
- 대상이 학생 계정이 아니거나 존재하지 않으면 `404`를 반환한다.
- 거부가 결정된 뒤에는 보고서 집계, 질문 생성, 점수 기록, 알림, 메일 작업을 실행하지 않는다.

## 검사 전략

- 각 취약 경로에 직접 요청하는 회귀 검사를 먼저 작성하고 현재 코드에서 실패하는지 확인한다.
- 다른 학교, 담당 밖 학급, 비공개 질문, 배정 밖 질문수업, 직접 번호 접근을 각각 검사한다.
- 자기 자료, 같은 학교 담당 학생, 직접 배정 수업의 정상 흐름도 함께 보존한다.
- 부분 검사가 끝나면 전체 단위 검사, 문법 검사, 형식 검사, 빌드를 차례로 실행한다.
