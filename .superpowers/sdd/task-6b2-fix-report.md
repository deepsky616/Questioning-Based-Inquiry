## 시험 우선 확인

제품 코드를 바꾸기 전에 검토 회귀 시험을 먼저 보탠 뒤 다음 명령을 실행했다.

```bash
npm test -- src/__tests__/ladder-game-flow.test.tsx
```

- 시험 열두 개 가운데 아홉 개 통과, 세 개 실패
- 밝은 화면 핵심 단추가 `bg-violet-700`을 쓰지 않아 대비 시험 실패
- 어두운 화면 핵심 단추가 `dark:bg-violet-300 dark:text-violet-950`을 쓰지 않아 대비 시험 실패
- 인공지능 시작점 선택 전에 학생 이름이 이미 배정 목록에 보여 중립 이름 시험 실패

실제 발판 배정과 늦은 응답은 제품 동작 자체보다 이전 시험의 거짓 양성 가능성을 지적한 항목이었다. 강화 시험이 고장을 잡는지 다음 임시 변이로 확인하고 바로 되돌렸다.

```bash
npm test -- src/__tests__/ladder-game-flow.test.tsx -t '혼자 하기에서 시작점을 고른 뒤에만'
```

- 작성기에 실제 도착 주제 대신 시작 열 주제를 넘기는 임시 변이에서 좁은 시험 한 개 실패
- 그림은 시작 하나에서 도착 `D`, 배정 주제 `주제 D`를 보였지만 작성기는 `주제 A`를 보여 실패함
- 변이를 되돌리고 실제 도착 배정을 다시 사용함

```bash
npm test -- src/__tests__/ladder-game-flow.test.tsx -t '지난 라운드의 늦은 인공지능 응답'
```

- 요청 번호와 라운드 열쇠 확인을 없앤 임시 변이에서 좁은 시험 한 개 실패
- 첫째 라운드의 늦은 질문이 둘째 라운드 질문을 덮는 것을 `act` 안의 약속과 미세 작업 소진 뒤 확인함
- 변이를 되돌리고 두 확인 조건을 모두 보존함

## 보정 내용

- 새 사다리 그리기와 다음 라운드 단추에서 인라인 초록 그라데이션을 없앴다.
- 밝은 화면은 `bg-violet-700 text-white`를 사용하며 계산 대비는 `7.10:1`이다.
- 어두운 화면은 `dark:bg-violet-300 dark:text-violet-950`을 사용하며 계산 대비는 `8.25:1`이다.
- 두 핵심 단추가 같은 검증된 색 짝을 쓰도록 한 상수로 묶었다.
- 인공지능 모드는 선택 전 두 배정을 `시작 1`, `시작 2`로만 표시한다.
- 시작점을 고른 뒤에만 선택 열을 학생 이름, 다른 열을 인공지능 이름으로 표시한다.
- 고정 난수는 매 시험에서 실제 가로 발판을 만들고 혼자 하기에는 발판 셋, 인공지능 함께 하기에는 발판 하나를 만든다.
- 혼자 하기 시작 하나가 도착 `D`와 `주제 D`, 인공지능 시작 둘이 도착 `A`와 `주제 A`로 이어지는 실제 배정을 그림과 작성기에서 확인한다.
- 난수 호출 횟수 단언을 없애고 각 라운드의 실제 도착 주제 작성 화면을 확인한다.
- 늦은 응답 시험은 지연 약속을 `act` 안에서 해결하고 후속 미세 작업까지 비운 뒤 현재 둘째 질문 유지와 첫째 질문 부재를 함께 확인한다.

## 자기 검토

- 최종 제품에는 두 임시 고장 변이가 남지 않았음을 확인했다.
- 실제 도착 주제는 다시 `selectedAssignment.topic`에서만 작성기로 전달한다.
- 인공지능 응답은 요청 번호와 라운드 열쇠가 모두 맞을 때만 반영한다.
- 핵심 동작 단추에는 `game.gradientCss` 인라인 배경이 없고 머리글의 기존 꾸밈 배경만 유지한다.
- 보정 커밋에는 허용된 지역 화면과 흐름 시험 두 파일만 들어갔다.
- 서버, 자료 저장, 친구 방 화면과 기존 문구 파일은 바꾸지 않았다.

## 남은 걱정

- 대비 시험은 현재 프로젝트가 덮어쓰지 않는 기본 보라 색값을 계산한다. 나중에 보라 색판을 바꾸면 클래스와 계산값을 함께 갱신해야 한다.
- 실제 기기 화면 갈무리 대신 렌더된 클래스와 계산 대비로 확인했다.
- 지난 인공지능 요청 자체를 취소하지는 않으며, 완료된 늦은 응답을 화면 상태에 반영하지 않는 방식이다.
