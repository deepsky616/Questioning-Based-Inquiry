# 작업 5가 보고서

## 구현

- 한국어와 영어 이름 및 별칭과 열네 속성값을 가진 내장 물건 자료를 추가했다.
- 질문에서 지원 속성이 정확히 하나일 때만 `yes` 또는 `no`를 만들고, 한 번 부정은 뒤집으며 겹친 부정은 `unknown`으로 처리한다.
- 추측은 `NFKC`, 앞뒤 공백 제거, 이어진 공백 축약과 영어 소문자 변환 뒤 이름 또는 별칭 전체와만 맞춘다.
- `mystery-box`를 중앙 정적 판정기 등록부에 넣었다. 미스터리 판정기의 중앙 판정기 가져오기는 형 전용이라 실행 중 순환은 없다.
- 일반 시작은 비밀 없는 버전 2 `setup` 상태를 만들고, 방장 `mystery-start`가 서버 물건과 첫 라운드 및 차례를 정한다.
- 질문은 서버 판정 기록과 질문자 점수만 더하며 차례, 활동 수와 라운드를 넘기지 않는다.
- 틀린 추측만 활동과 라운드 및 차례를 한 번 넘긴다. 정답 또는 스무 번째 오답은 같은 저장 후보에서 기록, 공개 정답과 방 종료를 함께 만든다.
- 저장 상태와 공개 상태 판독을 분리했다. 비공개 물건 식별값은 저장된 `gameState.private.itemId`에만 있고 공개 판독은 `private`이 있으면 거절한다.
- 같은 명령 재생, 재접속 상태, 진행 전과 진행 중 이탈, 참가자 부족 종료와 실제 요청 경로의 성공 및 조회 및 재생 및 충돌 및 나가기 및 다시 시작 응답을 시험했다.

## 시험 우선 확인

- 순수 규칙 첫 실행은 새 모듈을 찾지 못해 시험 파일 1개가 실패했다.
- 순수 규칙 첫 구현 뒤 모호한 한국어 부정 1개가 `unknown` 대신 `no`로 나와 실패했고 `아닌` 꼴을 별도 부정으로 세어 고쳤다.
- 첫 엔진 실행은 등록 판정기가 없어 준비와 방장 시작 2개가 `changed` 대신 `corrupt`로 실패했다.
- 질문과 차례 시험은 지원 명령 부재로 3개가 실패했다.
- 틀린 추측, 정답, 스무 번째 오답은 각 흐름을 넣기 전에 각각 1개가 `invalid`로 실패했다.
- 참가자 부족 종료는 공개 정답이 없어 1개가 실패했다.
- 기존 등록부 시험은 미스터리 판정기 추가 뒤 기대값이 달라 1개가 실패했다.
- 엄격 저장 판독 시험은 비공개 물건 누락, 라운드 불일치, 차례 범위, 점수 관계, 조기 정답 공개와 알 수 없는 물건 6개를 처음에 받아들여 실패했다.
- 공개 상태 전용 판독 시험은 함수가 없어 1개가 실패했다.
- 자기 검토에서 물건 준비 전 참가자 부족 종료 상태를 다시 읽지 못하는 1개 실패를 확인해 고쳤다.
- 첫 형 검사는 공개 정답의 좁힌 형이 배열 찾기 콜백에서 유지되지 않아 2개 오류가 났고, 검증된 지역 상수로 고친 뒤 통과했다.
- 실제 요청 경로의 공개 변환은 기존 공용 변환기가 이미 원본 불변과 비공개 제거를 만족해 처음부터 통과했으며 제품 요청 경로는 바꾸지 않았다.

## 남은 우려

- 이번 묶음은 순수 규칙, 서버 상태와 비공개 응답만 맡았다. 친구 방 화면과 지역 화면 종료 연결은 작업 5나 범위다.
- 질문 판정은 의도대로 고정 표현 사전을 사용한다. 지원하지 않는 표현은 `unknown`이며 자유 입력을 외부 추론에 보내지 않는다.
- 내장 물건 목록과 지역 화면의 기존 목록은 아직 서로 다른 파일에 있다. 화면 파일을 바꾸지 말라는 범위에 따라 이번 작업에서는 합치지 않았다.
- 전체 저장소 시험과 제품 빌드는 이번 작은 묶음의 완료 기준이 아니어서 실행하지 않았다. 지정 시험과 형 검사 및 수정 파일 코드 검사만 실행했다.
- 데이터베이스와 자료 이전 파일은 바꾸지 않았다.
