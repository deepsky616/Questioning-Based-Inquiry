## 시험 우선 확인

1. 판정기 모듈을 만들기 전에 시작 상태 시험을 작성했다. 첫 실행은 `ladder` 모듈을 찾지 못해 시험 묶음이 실패했다.
2. 초기 상태와 정적 등록만 추가해 첫 시험 하나가 통과하는 것을 확인했다.
3. 엄격한 상태 판독, 주제 준비, 질문 제출, 세 라운드 전이와 이탈 시험을 먼저 늘렸다. 이때 전체 서른여섯 개 가운데 스물아홉 개가 명령 구현 부재로 실패했다.
4. 최소 서버 판정 구현 뒤 서른여섯 개가 모두 통과했다.
5. 실제 방 경로에 참가자 저장 경합 시험을 추가했다. 경로 본문에 동작 이름이 포함되어 첫 응답이 기대한 `409`가 아닌 `400`으로 실패하는 것을 확인했다. 동작 이름만 선택적으로 허용하고 현재 동작과 같은지 검사한 뒤 통과했다.
6. 자기 검토에서 근거 질문이 없는 완료 상태와 끝난 방의 준비 재개를 찾았다. 두 실패를 재현한 뒤 완료 라운드 이력을 검사하고 방 상태 관계를 보강했다.
7. 방에 저장된 긴 참가자 이름과 앞뒤 공백이 임의 제한으로 거절되는 실패를 재현했다. 이름은 방 자료 그대로 저장하고 주제와 질문에만 길이 제한을 적용하도록 고쳤다.
8. 독립 검토에서 현재 완료 대상을 따로 저장하지 않아 이탈 뒤 완료 근거를 상태만으로 확인할 수 없는 문제를 확인했다. `roundTargetPlayerIds` 부재로 초기 상태, 준비, 제출, 다음 라운드와 이탈 시험이 실패하는 것을 먼저 확인했다.
9. 대상 전원이 제출된 진행 상태, 대상 두 명인 인원 부족 상태, 대상 질문이 빠진 완료 상태가 잘못 허용되는 시험을 추가해 실패를 재현했다. 진행은 미제출 대상이 남아야 하고, 완료는 셋째 라운드의 대상 전원이 제출해야 하며, 인원 부족은 대상이 한 명 이하여야 하도록 보강했다.
10. 지난 한 라운드에 서로 다른 가짜 참가자 아홉 명 질문을 넣어 기존 전체 상한만으로는 거절하지 못하는 경계를 재현했다. 라운드마다 최소 두 질문과 최대 여덟 질문을 따로 검사하도록 고쳤다.
11. 희소 배정, 질문, 바깥 및 안쪽 발판, 라운드 참가자와 대상 배열을 넣었을 때 예외 없이 `null`을 돌려주는 시험을 추가했다. 모든 필요한 배열의 실제 칸을 확인하고 전체 판독 경계를 예외 방어로 감쌌다.
12. 여덟 명 시작 뒤 여섯 명이 실제로 이탈하고 남은 두 대상이 세 라운드를 끝내는 시험을 추가했다. 이탈 때만 대상을 줄이고 제출과 다음 라운드는 저장된 대상 목록만 완료 근거로 쓰도록 고쳤다.

## 구현 결과

- `LadderRoomState`, `LadderAssignment`, `LadderQuestion`과 엄격한 `readLadderState`를 추가했다.
- 현재 라운드 원래 참가자와 완료 대상의 뜻을 `roundPlayerIds`, `roundTargetPlayerIds`로 분리했다.
- 상태, 배정과 질문의 허용 키를 정확히 검사하고 알 수 없는 키를 거절한다.
- 순수 사다리 함수로 열 수, 열 행 발판, 시작 및 도착 순열과 배정 주제를 다시 계산해 저장 관계를 확인한다.
- 질문 식별쌍 중복, 라운드별 식별값 관계, 학생당 세 질문과 방 전체 스물네 질문 상한을 검사한다.
- 이전에 끝난 각 라운드는 질문이 두 개 이상 여덟 개 이하인지 따로 검사한다.
- 준비, 진행, 완료와 인원 부족 종료의 라운드 및 질문 이력 관계를 구분한다.
- 진행 상태는 대상이 두 명 이상이며 미제출 대상이 남아 있어야 한다. 완료 상태는 셋째 라운드 대상이 두 명 이상이며 모두 제출해야 하고, 인원 부족 상태는 진행 뒤 대상이 한 명 이하여야 한다.
- `ladder-prepare`는 준비 단계의 방장만 현재 참가자 수와 같은 다듬은 주제를 보낼 수 있게 했다.
- 발판, 라운드 식별값, 참가자 이름과 배정은 서버 난수, 서버 식별값과 현재 방 자료만 사용한다.
- `ladder-submit-question`은 현재 라운드 참가자의 서버 배정, 언어, 질문 모양, 이백 자와 비속어를 검사한다.
- 첫째와 둘째 라운드의 마지막 활성 제출은 질문을 누적한 채 새 서버 발판과 식별값을 같은 변경에 만든다.
- 셋째 라운드의 마지막 제출은 방장 여부와 관계없이 같은 변경에서 `completed`로 끝낸다.
- 이탈 뒤 한 명만 남으면 공통 `insufficient-players`를 보존하고, 둘 이상 남아 현재 제출이 끝났으면 같은 이탈 결과에서 다음 라운드 또는 완료로 이동한다.
- 이탈 처리만 현재 방 참가자와의 교집합으로 대상 목록을 줄이며, 미제출 대상이 남으면 줄어든 목록을 같은 라운드에 저장한다.
- 진행 단계의 명령 경계는 저장된 대상 집합과 현재 방 참가자 집합이 정확히 같은지 먼저 확인한다.
- 배정, 질문, 발판, 참가자와 대상 등 필요한 모든 배열의 희소 칸을 거절하며 알 수 없는 판독 입력에서는 예외 대신 `null`을 돌려준다.
- 전환에 필요한 난수나 식별값 공급자가 없거나 잘못되면 임시 값을 만들지 않고 손상 결과로 거절한다.
- 실제 방 경로에서 다른 참가자의 저장이 먼저 성공한 경우 최신 방 `409`를 받은 뒤 같은 명령을 새 판본으로 다시 보내면 두 질문이 모두 보존됨을 확인했다.
- 정적 등록부에 `ladder`만 추가하고 기존 `memory`, `mystery-box` 등록을 유지했다.

## 남은 범위와 위험

- 혼자 하기, 인공지능과 함께하기와 친구 방 화면은 다음 작업 묶음에서 이 공개 상태와 두 서버 명령에 연결해야 한다.
- 화면 분류 결과는 학습 도움말로만 쓰며 이번 서버 상태에는 받거나 저장하지 않는다.
- 지난 라운드의 배정 전체를 따로 저장하지 않으므로 상태 판독은 지난 질문의 형, 라운드 관계와 라운드별 두 개에서 여덟 개 상한을 검사하고, 현재 라운드 질문만 현재 배정과 다시 맞춘다. 서버 명령 경로는 모든 질문의 이름과 주제를 당시 서버 배정에서만 만든다.
- 실제 두 브라우저 동시 조작과 밝고 어두운 화면 검사는 뒤쪽 통합 작업 범위다.
- 자료 저장 구조나 기존 자료를 바꾸지 않아 자료 이전은 필요하지 않다.
