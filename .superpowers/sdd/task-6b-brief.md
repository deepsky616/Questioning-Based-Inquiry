# 작업 6나: 질문 사다리 공통 그림과 모든 모드 질문 흐름

먼저 작업 6 전체 계획과 최상위 설계, `.superpowers/sdd/task-6-analysis.md`, 검토를 통과한 `.superpowers/sdd/task-6a-report.md`와 실제 공개 상태 형을 읽는다. 이 묶음은 작업 6가의 순수 경로와 서버 상태를 화면에 연결하고, 혼자와 인공지능 모드에서도 학생 질문 셋을 확정해야 끝나도록 고친다.

## 시작 경계

작업 6가의 서버 계약을 화면에서 다시 구현하지 않는다. 친구 화면은 서버 `grid`, `assignments`, `questions`, `roundId`, 라운드와 끝 상태를 읽기만 한다. 지역 화면은 같은 순수 사다리 함수를 쓰되 지역 질문 기록과 세 라운드 흐름만 소유한다. 서버 판정기와 공개 형을 바꿔야 할 결함이 보이면 화면 우회 코드를 넣지 말고 작업 6가 보정으로 돌린다.

## `LadderBoard` 실제 경로

공통 그림은 안정된 `viewBox`, 열당 최소 너비와 바깥 가로 스크롤을 사용해 두 명부터 여덟 명까지 같은 좌표 규칙을 유지한다. 이름이나 주제 길이로 선 좌표와 그림 높이가 바뀌지 않게 한다.

그림 순서는 다음과 같다.

1. 모든 기본 세로선과 서버 또는 지역 그리드의 실제 가로 발판을 중립색으로 그린다.
2. 선택한 시작 열이 있으면 `buildLadderPathSegments`가 돌려준 구간만 굵게 덧그린다.
3. 선택했다는 이유로 시작 세로선 전체의 기본색을 바꾸지 않는다.
4. 경로가 열을 바꿀 때 실제 가로 발판을 따라 이동하고 대각선이나 도착점 직선 잇기를 만들지 않는다.
5. 경로 마지막 열에 끝 표식을 두고 시작 표식, 끝 표식과 배정 문구를 함께 제공한다.

그림 안의 긴 이름과 주제는 좌표를 밀지 않도록 짧은 표지만 쓰고, 그림 아래 배정 목록에서 전체 이름과 전체 주제를 줄바꿈 가능한 글자로 보여 준다. 여덟 열 모바일에서는 그림만 가로로 움직이고 라운드 표시, 질문 입력과 단추는 화면 너비 안에 남아야 한다.

## `LadderQuestionComposer` 질문 확인

공통 작성 구성 요소는 `writing`, `checking`, `review`, `check-failed` 네 상태와 현재 입력을 소유한다. `roundKey`가 바뀌면 이전 입력, 분류 도움말과 늦은 응답을 새 라운드에 남기지 않는다.

- 분류 요청 전에 앞뒤 공백 제거, 빈 값, 현재 언어의 `isQuestionFormForLocale`와 `QUESTION_GAME_LIMITS.question`을 검사한다.
- 잘못된 문장이나 이백일 자는 `/api/classify`를 부르지 않고 입력 가까이에 오류를 보인다.
- 분류 성공은 열린 정도, 질문 유형, 까닭과 도움말을 보여 주고 `고쳐 쓰기`와 `확정`을 제공한다.
- 사실 질문과 닫힌 질문도 놀이에서 유효하므로 분류 결과로 확정을 막지 않는다. 부적절 도움말도 고쳐 쓰기를 강하게 권하지만 서버 판정을 대신하지 않는다.
- 분류 실패, 응답 형 오류와 호출 제한 뒤 입력을 그대로 두고 `다시 확인`과 `도움말 없이 확정`을 함께 제공한다.
- 질문을 고치면 이전 분류 결과를 버리고 다시 확인하게 한다.
- 늦은 응답은 요청 식별값 또는 취소 신호와 `roundKey`를 모두 확인해 새 입력을 덮지 못하게 한다.
- `onConfirm(question)`은 `Promise<boolean>`이며 참인 경우에만 입력과 확인 상태를 비운다. 거절, 통신 실패와 `409`에서는 그대로 둔다.

분류 요청에는 질문 내용만 보내며 서버 명령에는 분류 결과, 배정, 이름과 경로 자료를 넣지 않는다.

## 혼자 모드

지역 상태는 `setup`, `reveal`, `compose`, `round-summary`, `done`과 현재 `1..3` 라운드를 분명히 가진다.

- 네 시작점과 네 주제를 준비하고 공통 순수 함수로 라운드마다 새 사다리를 만든다.
- 학생이 시작점 하나를 고르기 전에는 질문 입력을 열지 않는다.
- 선택한 실제 경로와 배정 주제를 확인한 뒤 그 주제로 질문을 작성하고 검토한다.
- 확정한 질문, 주제와 라운드를 누적 보존하고 요약 뒤 새 사다리와 새 선택으로 넘어간다.
- 1, 2 라운드에는 완료 화면이나 점수 요청이 없고, 세 번째 질문 확정 뒤에만 `done`으로 이동한다.
- `useSingleAward`와 `AwardBadge`를 제거하고 혼자 활동에서 서버 점수 요청을 보내지 않는다.

## 인공지능 모드

- 학생과 인공지능 친구 두 시작점의 배정을 같은 사다리에서 보여 준다.
- 학생은 자기 배정 주제로 매 라운드 질문 하나를 확인하고 확정한다.
- 인공지능 예시는 인공지능 배정 주제로 만들고 학생 질문과 나란히 보여 준다.
- 예시 생성 실패, 지연과 빈 응답은 학생 작성, 도움말 없는 확정과 다음 라운드를 막지 않는다.
- 늦은 예시 응답이 다음 라운드의 주제에 붙지 않게 라운드 식별값을 확인한다.
- 학생 질문 셋을 확정하기 전에는 끝내지 않고 어떤 점수 요청도 보내지 않는다.

## 친구 모드

`RoomLadder`는 작업 6가의 엄격한 공개 상태를 읽어 서버 표현 화면으로 바꾼다.

- `setup`에서는 방장만 현재 참가자 수의 주제를 입력해 `ladder-prepare`를 보낸다. 다른 참가자는 준비 대기를 본다.
- 준비 본문에는 공통 명령 필드와 `topics`만 넣고 발판, 배정, 이름, 참가자 식별값과 라운드 식별값을 만들지 않는다.
- 진행 중에는 자기 배정의 `startColumn`으로 실제 경로를 그리고, 전체 배정 주제, `round / maxRounds`와 현재 라운드 제출 현황을 보여 준다.
- 제출 여부와 진행 수는 반드시 `(roundId, playerId)`로 계산한다. 지난 라운드 질문 하나가 새 라운드 입력을 막지 않는다.
- 확정할 때 `ladder-submit-question`에 공통 명령 필드, 현재 `playId`, `roundId`, 좁힌 `ko | en`과 질문만 보낸다.
- `409`, 서버 거절과 통신 실패 뒤 입력을 유지하고, 새 방 버전을 받은 뒤 같은 질문을 다시 보낼 수 있다.
- 이미 낸 학생은 현재 라운드 대기와 다른 학생의 제출 현황을 본다.
- 서버가 만든 새 `roundId`가 오면 작성 구성 요소를 새로 시작한다.
- 완료 상태는 세 라운드 누적 질문과 학생별 셋 이하의 결과를 보여 주고 수동 종료 단추를 만들지 않는다.
- `set-state`, `update-state`, 지역 `Math.random`, 클라이언트 `status: "ended"`와 종료 판정을 모두 제거한다.

## 밝고 어두운 화면

- 그림 기본선은 흰 바탕에서도 계산 대비 `3:1` 이상인 중립색, 어두운 카드에서도 `3:1` 이상인 짝 색을 쓴다.
- 선택 경로도 두 화면에서 `3:1` 이상이어야 하며 색만으로 시작과 끝을 알리지 않는다.
- 이름, 주제, 도움말, 실패와 대기 글자는 해당 카드 배경에서 `4.5:1` 이상이어야 한다.
- 고정 `#d1d5db`, `#9ca3af`, `#6b7280`, `bg-white`, `text-gray-*`를 새 사다리 구성 요소의 의미 색으로 쓰지 않는다. 화면 주제에 맞는 의미 클래스와 명시적인 밝고 어두운 짝을 사용한다.
- 작성, 확인, 검토, 실패, 제출 완료와 결과 상태를 밝은 화면과 어두운 화면으로 각각 렌더링해 글자와 입력이 보이는지 시험한다.
- 작은 화면과 넓은 화면에서 여덟 열, 긴 이름과 팔십 자 주제, 이백 자 질문이 서로 겹치거나 카드 밖으로 넘치지 않아야 한다.

## 시험 우선

먼저 `ladder-game-flow.test.tsx`에서 시작점 선택 전 입력 없음, 혼자와 인공지능 배정, 질문 아닌 문장과 이백일 자 거절, 분류 성공 뒤 고쳐 쓰기와 확정, 분류 실패 입력 보존과 도움말 없는 확정, 늦은 응답 무시, 확정 실패 보존, 세 번째 질문만 완료, 인공지능 실패 비차단과 점수 요청 없음을 실패시킨다.

다음으로 `room-ladder-flow.test.tsx`에서 방장 준비 본문, 참가자 실제 경로, 라운드 식별값별 제출 현황, 질문 확인 성공과 실패, 좁은 제출 본문, `409` 뒤 입력 보존, 새 라운드 초기화, 완료 누적 결과와 금지 명령 부재를 실패시킨다. 고정 그리드의 가로 이동 구간을 실제 `line` 좌표 또는 접근 가능한 경로 자료로 확인해 시작 열 전체 강조만으로 통과하지 못하게 한다.

`room-action-inputs.test.tsx`는 새 버전 2 상태와 `ladder-submit-question`을 사용하면서 실패 뒤 입력 유지, 성공 뒤 비우기 계약을 보존한다. 밝고 어두운 화면 시험은 두 화면 흐름 시험에 직접 넣고, 필요하면 계산 대비 도우미를 사용한다. 데이터베이스는 쓰지 않는다.

집중 시험은 다음 묶음을 최종으로 다시 실행한다.

```bash
npm test -- src/__tests__/question-ladder.test.ts src/__tests__/ladder-game-flow.test.tsx src/__tests__/question-game-room-engine-ladder.test.ts src/__tests__/room-ladder-flow.test.tsx src/__tests__/room-action-inputs.test.tsx src/__tests__/question-game-room-engine.test.ts
npx tsc --noEmit
```

## 완료 기준

- 공통 그림이 실제 순수 선분만 강조하고 두 명부터 여덟 명까지 배정과 같은 도착점을 보임
- 혼자와 인공지능에서 학생 질문 셋, 친구에서 모든 활성 참가자의 세 라운드 질문이 있어야 완료됨
- 분류 실패가 어느 모드의 입력과 진행도 막지 않음
- 친구 화면이 두 서버 명령만 쓰고 서버 상태, 배정과 종료를 지역에서 만들지 않음
