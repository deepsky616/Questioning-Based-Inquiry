# 작업 5나 보고서

## 구현

- 새 `RoomMysteryBox` 화면을 놀이 방 지도에 등록하고 친구 모드의 지역 미스터리 대체 실행을 제거했다.
- 방 화면은 `readMysteryPublicState`가 검증한 공개 상태만 읽는다. 진행 전 비밀 물건과 저장 전용 필드는 읽거나 화면 상태로 만들지 않는다.
- 방장 수동 시작, 질문, 추측과 결과 다시 시작을 각각 `mystery-start`, `mystery-ask`, `mystery-guess`, `restart`로만 보낸다. 일반 상태 덮어쓰기와 점수 공유는 사용하지 않는다.
- 질문과 추측을 서로 다른 입력으로 두고 현재 서버 차례, 실행 식별값, 라운드 식별값과 전체 기록 길이로만 입력 가능 여부와 남은 활동을 정한다.
- 같은 화면 갱신 안의 연속 누르기를 요청 참조로 즉시 막는다. 연결 실패 뒤 같은 질문 또는 추측은 종류별 같은 명령 식별값을 다시 쓰고, 성공 또는 최근 명령 목록에서 서버 반영을 확인했을 때만 해당 입력을 비운다.
- 방 번호와 생성 시각을 요청 수명으로 묶어 이전 방 응답이 새 방 입력을 지우지 않게 했다.
- 모든 참가자가 같은 기록, 판정, 현재 차례, 라운드, 질문 수와 결과를 본다. 정답은 완료된 공개 상태에서만 표시한다.
- 결과는 정답 성공, 스무 활동 종료, 시작 전 참가자 부족과 진행 중 참가자 부족을 구분한다. 떠난 참가자의 이름도 기록에서 복원한다.
- 지역 `MysteryBoxGame`은 공통 규칙의 모드별 스무 활동을 읽는다. 질문 또는 추측을 한 활동으로 기록하고, 혼자 첫 오답은 같은 학생이 계속하며 인공지능 모드 오답은 다음 차례로 넘긴다.
- 지역 화면의 스물한 번째 강제 추측 단계를 없앴다. 스무 번째 질문 또는 오답은 바로 실패 종료하고 정답 추측은 즉시 성공 종료한다.
- 지역 질문 수는 실제 질문 기록만 세며 추측은 활동 기록에만 포함한다.
- 지역 정답 판정은 공통 미스터리 규칙의 정규화와 전체 일치를 사용한다. 기본 물건은 두 언어 이름과 별칭을 허용하고, 인공지능이 만든 임의 물건은 정규화한 이름 전체가 같을 때만 정답이다.
- 인공지능 답변을 기다리는 동안 질문 반복과 추측 전환을 참조 잠금으로 즉시 막는다. 추측도 엔터와 단추가 같은 화면 갱신 안에서 겹쳐도 한 번만 기록하고, 새 기록이 그려진 뒤 잠금을 푼다.
- 인공지능 호출의 `null` 실패와 실제 모름 답변을 구분한다. 사람 질문 실패는 입력, 활동 수와 차례를 보존하고, 인공지능 차례 만들기나 답 요청 실패는 활동을 쓰지 않은 채 사람 차례로 안전하게 돌려보낸다.
- 방과 지역 화면의 기록, 판정, 입력과 결과에 주제 색 토큰과 밝고 어두운 화면용 대비 색을 적용했다.
- 문자열 인덱스가 있는 기반 상태 때문에 공개 상태의 알려진 필드가 `unknown`으로 넓어지던 형을 명시적 공개 필드 `Pick`으로 바로잡았다. 실행 동작은 바꾸지 않았다.

## 시험 우선 확인

- 제품 수정 전 새 화면 시험은 `RoomMysteryBox` 모듈을 찾지 못해 시험 묶음 한 개가 실패했다.
- 방 화면을 처음 연결한 뒤 스물두 시험 중 열세 개가 통과하고 아홉 개가 실패했다. 남은 제품 실패는 놀이 지도 미등록, 지역 첫 오답 즉시 종료, 스무 활동 뒤 강제 추측과 고정 상한 및 주제 색이었다. 완료 상태 고정 자료 한 건과 중복 문구 조회 두 건은 시험 자료와 조회를 바로잡았다.
- 지역 흐름 보정 뒤 방 및 지역 스물두 시험이 모두 통과했다.
- 어두운 화면 결과 기록 시험은 기존 공용 회색 기록 구성요소 사용으로 한 건 실패했다. 미스터리 전용 주제 토큰 기록으로 바꾼 뒤 통과했다.
- 질문 연결 실패 뒤 추측을 시도하면 질문 재시도 식별값을 잃는 시험 한 건이 실패했다. 질문과 추측별 재시도 자료를 따로 보관한 뒤 통과했다.
- 시작 안내가 여전히 질문 수처럼 읽히는 시험 한 건이 실패했다. 질문 또는 추측을 합친 스무 활동 안내로 바꾼 뒤 통과했다.
- 전체 시험 첫 실행은 옛 지역 친구 대체 경로를 기대한 방 동기화 정책 시험 한 건만 실패했다. 오류 알림을 유지하면서 등록되지 않은 방을 안전 안내로 닫는 새 정책으로 시험을 갱신한 뒤 전체 시험이 통과했다.

## 첫 검토 보정

- 지역 정답 판정이 부분 문자열을 허용해 `사`를 `사과` 정답으로 처리하고 영문 대소문자를 일관되게 처리하지 못하는 실패를 재현했다. 정규화한 전체 이름 비교와 공통 기본 물건 별칭 판정으로 바꿨다.
- 인공지능 답변이 늦을 때 질문 단추를 빠르게 두 번 누르거나 추측으로 바꾸면 요청과 활동이 겹치는 실패를 재현했다. 비동기 호출 전에 참조 잠금을 걸고 성공, 오류와 새 게임에서 풀도록 바꿨다.
- 방에서 앞뒤 공백을 포함해 쓴 질문과 추측은 정리한 값으로 전송되지만 성공 또는 최근 명령 확인 뒤 원래 입력이 지워지지 않는 실패를 재현했다. 현재 입력도 앞뒤 공백을 정리해 전송값과 비교하되, 실제 내용이 바뀐 입력은 보존하도록 바꿨다.
- 목록의 두 언어 안내가 여전히 질문 스무 개만 허용하는 것처럼 적혀 있었다. 질문과 추측을 합친 스무 활동으로 설명과 순서를 고쳤다.
- 제품 변경 전 관련 검사에서 열 건이 실패했고 보정 뒤 관련 여든여덟 검사가 모두 통과했다.

## 두 번째 검토 보정

- 실제 `useAIPlay.ask`가 오류 때 예외가 아니라 `null`을 반환하는 계약을 시험에 반영했다. 사람 질문의 `null`을 모름 답변으로 기록해 활동과 차례를 쓰는 실패를 재현하고, 실패 결과와 정상 답변 결과를 구분하는 반환형으로 바꿨다.
- 실제 모름 응답 객체는 정상 활동으로 기록하면서, `null` 실패는 질문 입력, 활동 수와 사람 차례를 보존하고 잠금만 풀도록 확인했다.
- 인공지능 차례 만들기나 이어지는 답 요청이 `null`이면 대체 질문을 잘못 기록하거나 추가 요청을 내보내는 실패를 재현했다. 실패 때 활동을 쓰지 않고 사람 차례로 돌아오게 했다.
- 추측 입력에서 엔터와 제출 단추를 같은 화면 갱신 안에 이어 실행하면 기록은 한 건처럼 보여도 차례가 두 번 늘어 사람에게 되돌아오는 실패를 재현했다. 추측 함수 진입 즉시 참조 잠금을 걸고 기록이 반영된 다음 화면 갱신에서 풀도록 바꿨다.
- 새 검사 다섯 건 가운데 실제 모름 구분 한 건은 처음부터 통과했고, 나머지 네 건은 의도대로 실패한 뒤 보정 후 미스터리 화면 마흔한 검사가 모두 통과했다.
