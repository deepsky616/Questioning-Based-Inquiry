# 작업 7라 서버 경계 보정 보고서

## 상태

`DONE`

완료된 네 차례 놀이의 이탈 기록, 카바 준비 전 인원 감소, 등록 판정기 방의 예전 직접 쓰기, 시작 본문 정확 키, 중앙 규칙 연결을 보정했다.

## 시험 먼저 확인

구현 전에 다음 실패를 확인했다.

- 완료된 이야기 주사위, 질문 주사위, 릴레이, 카바에서 참가자 이탈 뒤 기록이 잘리거나 `corrupt`가 됐다.
- 카바를 세 명으로 시작하고 준비 전에 한 명이 나가면 두 명용 여섯 문장 계획을 읽지 못했다.
- 등록 판정기의 대기 방에서 `update-state`, `set-state`, `next-turn`, `set-topic`, `add-question`이 예전 저장 경로로 내려갔다.
- 시작 본문의 초과 필드가 초기 상태 생성을 막지 못했다.
- 추가 검토에서 기록된 시작 명령의 초과 필드가 `replayed`로 우회되는 실패도 확인했다.

## 구현 내용

- 끝난 방의 나가기는 놀이 기록을 다시 해석하거나 줄이지 않고 참가자와 방장만 갱신한다. 마지막 참가자도 `changed`와 빈 참가자 목록을 돌려 빈 방 삭제 경로를 막지 않는다.
- 카바의 아직 준비하지 않은 상태에서만 현재 방 참가자, 이름표, 영점 점수표를 다시 맞춘다. 진행 기록이 생긴 뒤의 역사 자료는 유지한다.
- 등록 판정기의 대기 방은 다섯 예전 직접 쓰기를 저장 전에 거절한다. 옛 진행 방은 기존의 새 규칙 다시 시작 안내와 `409`를 먼저 유지한다.
- 시작 본문은 `commandId`, `expectedCreatedAt`, `expectedVersion`, 선택 `action`만 허용하며 재전송 판정보다 먼저 정확 키를 검사한다.
- 네 놀이의 인원 제한과 라운드 목표, 읽기 상한, 이탈 완료 경계를 각각 `QUESTION_GAME_RULES`에서 파생한다.
- 이야기 완결 묶음 수는 별도 저장 필드가 아니라 `pairs.length`에서 파생하도록 계획 문구를 바로잡았다.
