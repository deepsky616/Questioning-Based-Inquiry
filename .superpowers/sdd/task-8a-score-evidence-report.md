## 시험 우선 기록

1. 구현 파일을 만들기 전에 대상 시험을 작성했다.
2. 첫 실행은 새 모듈을 찾을 수 없어 예상대로 실패했다.
3. 일곱 엄격 판독기와 공통 규칙을 연결한 뒤 대상 시험 열아홉 개가 통과했다.
4. 검토 중 짝 찾기 판독기만으로는 친구 방 인원 하한을 보장하지 못하는 경계를 찾았다.
5. 한 명짜리 완료 방 거절 시험을 추가해 기존 구현이 받는 실패를 확인했다.
6. 공통 규칙의 두 명에서 여덟 명 범위를 연결한 뒤 대상 시험 스무 개가 모두 통과했다.

## 구현 계약

- 상태 버전 `2`, 점수 근거 버전 `2`, 점수 키 버전 `2`, 올바른 실행 식별값을 모두 요구한다.
- 방 상태가 종료이고 놀이 단계가 완료이며 종료 사유가 `completed`일 때만 근거를 만든다.
- 일곱 게임마다 기존 엄격 판독기를 사용해 손상된 저장 상태를 거절한다.
- 저장 참가자 식별값과 이름이 현재 방 참가자와 맞는지 다시 확인한다.
- 참가 인원과 학생별 및 방 전체 질문 상한은 `QUESTION_GAME_RULES`에서 직접 읽는다.
- 짝 찾기는 질문 수를 영으로 두고 획득 짝을 활동 점수로 쓴다.
- 이야기 주사위는 완료된 질문과 대답 쌍의 질문만 센다.
- 질문 주사위, 질문 릴레이와 질문 사다리는 서버가 확정한 질문만 센다.
- 미스터리 박스는 질문 기록만 세고 추측은 제외한다.
- 까바 놀이는 맞다고 확정된 시도만 질문으로 세며 저장 점수와 다시 맞춘다.
- 경쟁 우승자는 전달된 담당 학생만이 아니라 방 전체 참가자 최고점으로 정한다.
- 짝 찾기와 까바 놀이만 양수 최고점 우승자를 만들며 영점수에서는 우승자를 만들지 않는다.
- 전달된 담당 학생 가운데 방 참가자만 결과에 넣고 영점수 학생도 보존한다.
